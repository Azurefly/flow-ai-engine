# AiFlowGraph 原始九页前端：页面—操作—状态对照矩阵

## 使用说明

本矩阵仅整理当前可读取安装包文件直接提供的证据。表中“当前映射”描述 Flow AI Engine 已存在的对应能力；“待补齐”不是功能缺失的推断，而是原始页面可见细节或行为尚未通过本轮代码和测试证明。`designProcess/bundle.js`、`canvas.js` 以及若干 AMD 模板未保留，因此其中不可见的内部字段不能视作已经从原始项目复原。

## 3. 流程设计器：`design_process.html`

### 3.1 工具栏节点（顺序为原始页面顺序）

| 原始标识 | 展示文案 | 原始状态 | 当前节点类型 | 执行或安全边界 |
|---|---|---|---|---|
| `start-node` | 开始 | 可拖入 | `start` | 初始化 `initialVariables`。 |
| `end-node` | 结束 | 可拖入 | `end` | 根据 `resultTemplate` 输出结果。 |
| `basic-node` | 状态节点 | 可拖入 | `state` | 输出状态代号、名称、类型。 |
| `operate-node` | 操作节点 | 可拖入 | `operate` | 持久化人工待办、领取和服务端续跑。 |
| `route-node` | 路由节点 | 可拖入 | `router` | 规则命中后按连线句柄分派。 |
| `subprocess-node` | 子流程 | 可拖入 | `subflow` | 仅当前所有者的已启用私有子流程。 |
| `rest-node` | REST节点 | 可拖入 | `rest` | SSRF、端口、协议、响应大小与重定向限制。 |
| `sql-node` | SQL节点 | 禁用 | `sql` | 控制/状态画布不允许绕过 P2 数据策略执行。 |
| `business-resource-btn` | 业务资源 | 禁用 | 资源入口占位 | 当前保留禁用可见状态。 |
| 无明确 id | 物理资源 | 禁用 | 资源入口占位 | 当前保留禁用可见状态。 |

## 继续恢复的执行顺序

第一步是将流程详情从简化弹层提升为含“流程引导—基本信息—只读流程图—实例列表”的可关闭详情视图，并按数据流/非数据流展示不同运行表。第二步是为流程仓库补齐原始搜索、批量菜单和预览工具。第三步是对数据流画布和数据流详情独立补齐资源树、工具栏、运行反馈与操作审计。最后才将所有页面的可见状态与服务端资源级权限、临时角色和数据隔离进行真实浏览器验收。
