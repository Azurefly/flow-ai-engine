## 三、测试中发现的缺陷与修复闭环

### 缺陷 1（高危）：操作节点显式多出口模式下无法连接多条分支连线
- **缺陷位置**：`client/src/components/WorkflowCanvas.tsx:112`
- **缺陷现象**：
  流程设计中心中，用户为审批操作节点配置了显式出口模式（`outcomeMode === "explicit"`），分别定义了“同意”与“驳回”两个 Handle 出口。但是在画布中连接第一条线（如同意 -> 下一状态）后，尝试从“驳回”Handle 连接至驳回处理状态时，画布提示无法连线，操作被静默阻止。
- **根本原因**：
  `canConnectCanvasNodes` 中将操作节点简单视为单一出线节点：
  ```ts
  // 修复前：
  const outgoing = edges.filter(edge => edge.source === source.id);
  if (
    ["start", "operate", "rest"].includes(source.data.kind) &&
    outgoing.length > 0
  )
    return false;
  ```
  该逻辑未判断操作节点当前的 `outcomeMode`。即使操作节点渲染了多个出口 Handle，只要存在 1 条已出线，后续连线就全被误判拦截。
- **修复方案**：
  在 `canConnectCanvasNodes` 中检测操作节点是否处于显式模式。若为显式模式（`isExplicitOperate`），则放行多分支连线建立；仅在非显式传统模式（`legacy_cancel`）或 start/rest 节点下维持单连线限制：
  ```ts
  // 修复后：
  const outgoing = edges.filter(edge => edge.source === source.id);
  const isExplicitOperate =
    source.data.kind === "operate" &&
    readOperateOutcomeMode(source.data.config) === "explicit";
  if (
    (["start", "rest"].includes(source.data.kind) ||
      (source.data.kind === "operate" && !isExplicitOperate)) &&
    outgoing.length > 0
  )
    return false;
  ```
- **验证结论**：
  固化用例 `TC-MOD1-CONN-001` 验证通过，操作节点在显式出口模式下可分别顺畅连接同意、驳回等多个分支。全量回归测试全部通过。
