## 本轮结论

原始页面在本地浏览器中的无样式渲染仍保留了可审计的 DOM 结构和原始文案：业务中心以筛选区、列表标题和表格为主；流程设计器由节点工具、画布工具、配置状态和右侧“配置信息”面板构成。由于完整 CSS 与安装包缺失，本轮将先以这些**可证明结构**约束高保真还原，并明确将色彩和像素级细节标注为“待完整归档复核”。

业务工作区原始结构可确认“返回业务中心 + 业务选择上下文 + 左侧模块菜单 + 右侧内容页签”的层级；已启动流程原始页面在裁剪副本中完全依赖缺失脚本，因此没有可呈现内容。后续视觉修复将优先消除当前控制台中与原始页面不相符的暗色品牌顶栏、营销式术语、过度圆角卡片和仪表盘化留白，使核心区域回归简约的流程管理工作台。

首次壳层调整后的真实开发预览已采用白色标题栏、蓝色选中页签、浅灰工作区背景和低圆角细边框，导航与四个授权项目均正常加载。仍可见“NEBULA BUSINESS ENGINE”等非原始品牌术语，以及业务中心中过度卡片化、标题区留白与原始列表密度不一致的问题；这些列为下一批壳层和业务中心修复项。

第二次真实浏览器核验显示，顶栏已不再呈现深色主题，并以“AI FLOW GRAPH”替代非原始品牌；业务中心也已收敛为白底、紧凑标题和扁平表格。进入 `DEMO5A6A` 后，项目工作区仍比原始 `businessOverview.html` 更像现代卡片控制台：左侧 256px 菜单、右侧较大标题区和圆角筛选条需要进一步压缩为原始的窄菜单、薄分隔线与紧凑工作内容区域。

项目工作区完成压缩后，真实页面已形成约 216px 的平面左侧菜单和连续右侧流程表格，真实四条流程数据、筛选与横向时间审计表仍可访问。进入数据流设计器后确认核心左仓库—中央画布—右配置面板仍完整，但顶部权限说明、协作成员、运行输入等多个卡片区挤占了原始画布工作台高度；原始 `design_process.html` 证据仅支持“节点工具 + 画布工具 + 配置状态 + 右侧配置面板”，因此下一步应把辅助信息收敛为可折叠次级区域，使画布优先可见。

画布壳层调整触发热更新后，工作区先显示一次临时空表，随后恢复四条真实流程；该现象属于既有授权查询加载过程，横向时间审计容器仍可用。当前工作区已满足原始的左右工作台层级，但“当前业务”和辅助说明仍较醒目，下一轮将继续把设计器辅助区收敛为可折叠状态，避免干扰画布主区域。

已启动流程工作台现以窄平面左侧视图菜单和无卡片间隙的右侧连续内容区呈现；首次进入时“正在读取已启动流程”遮罩明确显示，而不以零计数误导。当前内部管理员在该会话下没有可见任务或流程实例，故看板保持加载态；未创建额外流程实例以避免破坏多用户隔离与真实运行数据。

流程仓库已完成连续三栏视觉收敛：左侧目录树、中间根目录流程列表、右侧简介/只读画布预览以薄竖向分隔线相连。真实会话默认 `OPS` 项目无根目录流程时，三个区域分别呈现受权限约束的搜索树、空列表和未选中预览状态；项目选择器仍保留，未进行导入、导出或目录写入。

刷新后的 `OPS` 仓库读取到一条真实根目录流程，树、列表与右侧预览保持三栏对齐，批量操作和目录移动控件仍受既有项目编辑权限控制。随后已安全返回业务中心，为资源中心的真实数据视觉验收准备项目上下文。

`DEMO5A6A` 项目在授权查询完成后恢复四条真实流程；窄左侧菜单、紧凑筛选条、流程类型/审核/发布状态和横向时间审计列在视觉收敛后仍完整可访问。资源中心入口已准备就绪，未在本步骤触发任何流程、运行或调度写入。

资源中心在加载后呈现一条真实内联数据源和一条真实资源探查记录。左侧工作区菜单、资源标签、结构化数据源字段及运行审计的权限边界均保持；表单没有暴露 JSON 文本输入。资源中心的数据流分栏视觉规则已绑定为平面连续工作区，但本轮未切换数据流标签或触发运行、保存、调度操作。

随后切换到真实“数据流”标签，资源树、函数树、交集/差集/并集/SQL/TSML/中间表工具、保存图片与整理画布入口均以薄分隔的连续工作区呈现。真实运行审计显示三条既有记录，均为成功状态；页面仅做查看，未触发数据流运行、保存、暂停或删除托管计划。

## 同尺寸业务中心直接对照（1280px）

原始 `businessCenter.html` 在当前裁剪副本中可见的结构是：左上标题与图标、极简关键词/创建时间双行筛选、右上 BDP 同步、业务列表标题及紧凑七列表格。当前真实业务中心已经采用白底、薄灰表格与右侧筛选条，但仍保留顶层四页签、内部身份栏、业务工作域与流程计数等为安全多项目系统新增的必要信息；这些不是原静态页面的像素复刻。当前开发版首屏连接状态已改为白色细边框加载反馈，不再出现深色全屏仪表盘背景。后续视觉工作将以保留安全必需信息为前提，继续压缩额外文案与标题高度。

业务中心标题前的非原始流程标识已隐藏，标题栏、筛选容器与业务列表外框均收敛为低密度白色连续表格。真实浏览器仍显示 4 个已授权业务和查询/重置/进入业务操作；未修改任何业务数据。

设计器视觉复验进入 `DEMO5A6A` 后，首次绘制暂时显示空流程表；该页面已有项目切换后异步查询的已知加载过程，不能将该短暂状态作为功能或视觉结论。后续只在真实流程记录加载完成后打开设计器，并保持只读浏览。

刷新开发预览后，认证等待阶段呈现白色页面与细边框加载反馈；授权查询完成后恢复 4 个真实业务项目。该过渡不再出现深色全屏加载页，且未影响业务中心的筛选或可见项目清单。

再次进入 `DEMO5A6A` 后，授权流程列表恢复 4 条真实记录；列表中的状态、审核、时间审计和设计入口可用。该加载后基线将用于验证设计器默认收起左侧流程仓库栏的主画布模式，验收不触发保存、发布或运行。

打开已发布数据流后，流程仓库栏默认收起，屏幕主区域由流程标题、操作条、结构化运行字段、双侧工具条、画布和配置信息面板组成。真实画布显示开始与结束节点、配置状态图例、画布操作提示与只读配置空状态；未点击保存、发布、运行、取消发布或修改任何节点。浏览器可访问树仍保留被收起的流程列表，使顶部导航按钮能够随时恢复流程选择功能。
