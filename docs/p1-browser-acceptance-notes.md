# P1 浏览器验收记录

## 人工任务与服务端续跑

在管理员内部会话中，于 `DEMO5A6A` 工作区从仓库导入“P1 浏览器人工审批流程”，随后完成项目审核和发布。通过设计器发起后，系统没有把 `operate` 节点作为失败或前端逐节点操作处理，而是在已启动流程的“我的看板”中创建了一条待办。

浏览器复验覆盖了原始已启动流程的信息架构：左侧展示**我的看板、日历、待办、已办、我发起、全部流程**，看板统计显示待办、我发起和全部可见均为 1；同一任务在“最近任务”中仅显示一次。打开待办后可读取操作说明与脱敏后的任务输入，管理员领取任务并提交 `{"decision":"approved"}`。

提交后页面自动转到运行详情。实例 `bb1576ca` 显示成功，节点日志中开始、人工资料核验和结束节点均为成功。人工节点输出持久化了处理人 `1470001` 与审批结果；结束节点输出为 `{"result":{"decision":"approved","request":"browser-manual"}}`，证明后继节点由服务端续跑。

## 系统配置

管理员浏览器页面已加载通用设置、审批配置、工作域配置与身份权限入口。真实数据库集成测试进一步验证非管理员不能读取或修改这些设置，管理员可持久化水印和审批规则，并创建、停用工作域。

## 配置消费复验

本轮以管理员界面临时将平台名称设为“Flow AI Engine · P1 验收”、启用“P1 浏览器验收水印”并保存。重新载入控制台后，顶部标识更新为该平台名称，页面显示 15 个斜向水印文本，证明公开通用设置被控制台实际读取和渲染。随后在同一页面恢复默认平台名称并关闭水印；公共配置查询失效后，顶部与覆盖层即时恢复默认状态，未保留验收标识。

`p1-system-config.integration.test.ts` 同时验证：启用审批规则时未审核项目流程不能发布；关闭规则后同一流程可发布；工作域可被关联到业务项目，项目列表返回域代号与名称，管理员工作域统计会反映关联项目数。
