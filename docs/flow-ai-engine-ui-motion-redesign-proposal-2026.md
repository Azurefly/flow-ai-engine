## 1. 评审结论与修订决策

保留“中性色工作台、画布优先、紧凑信息布局、克制动效”的方向。原 v2.0 的主要问题不是视觉方向，而是把设计愿景、现有能力和未验证的技术承诺混在一起，缺少业务状态、工程边界和可复现验收条件。本版替换原方案，以下决策优先于旧稿。

| 原方案问题 | 修订决策 | 实施约束 |
| --- | --- | --- |
| 声称 120fps、零重排、零风险、画布可视率 88% | 改为可测量的性能与面积指标 | 未测量不得填写提升比例；transform 不保证 GPU 合成或零卡顿 |
| 称已审查标杆产品内部技术栈 | 删除未有证据支撑的技术归因 | Linear、Dify、n8n 等仅作为视觉讨论背景，不作为工程依赖或合规结论 |
| 建议重写整个 `index.css` | 增量迁移现有语义变量和局部样式 | 保留 Tailwind v4 `@theme inline`、暗色模式、焦点和现有业务选择器 |
| 浅色辅助文字直接宣称 AA 达标 | 调整文字色，按实际前景/背景组合检测 | 不能以颜色名称或单个色值证明所有状态达标 |
| 给 React Flow 节点 transform 加全局 transition | 使用节点坐标状态驱动的可取消布局动画 | 节点和连线必须同步；拖拽不经过缓动 |
| 抽屉宣称不影响画布，线框却表现为固定分栏 | 桌面采用覆盖式非模态 Inspector | 容器尺寸不随开关变化；显式处理遮挡、焦点与可用视区 |
| 试跑按“拓扑顺序”瀑布点亮 | 按服务端真实执行记录展示 | 并行、重试、等待人工、轮询不可用都不能伪造成串行执行 |
| 加入跨项目搜索、单步、模板等未核实能力 | 区分现有能力、本轮新增展示、后续功能 | 不为线框伪造接口、运行结果或权限 |
| 固定测试数量和历史产物大小 | 以当前执行输出为准 | 构建门槛来自预算脚本，不放宽阈值以通过检查 |

### 1.1 本轮目标和非目标

必须完成：统一设计 Token、导航与表格整理、画布控件与 Inspector 重排、真实状态反馈、试跑双栏布局、键盘与减少动态效果支持，以及覆盖核心交互的回归证据。

本轮不新增：流程执行引擎、数据库表、权限模型、跨项目全文搜索、后端暂停/单步/取消接口、新布局算法包、节点类型、审批业务规则。已有功能必须保留。产品界面不展示无法执行的“单步调试”“纯仿真”等入口。

业务兼容优先级高于视觉统一。发现需修改后端契约才能实现的效果时，记录缺口并保留当前可用路径，不自行扩大为引擎重构。

## 3. 信息架构与空间规范

### 3.1 导航层级

维持现有业务层级：全局工作台 → 业务项目 → 流程列表 → 流程设计/详情；已启动流程、仓库与系统配置仍使用已有入口。顶栏的导航是页面导航，语义使用 `nav` 与当前页面标识；局部结果切换才使用 Tab，不把所有导航一律改为 Tab role。

顶栏默认高度 48px，设计器工具栏 44px；多语言、200% 页面缩放时允许高度增长。当前业务名称需保持可见，长名称省略但可通过焦点/详情读取全名。项目切换只列用户可访问的项目；切换前处理未保存修改，切换后清理旧项目选择、面板和异步结果。

本轮 `Ctrl+K` 只做当前可访问、已加载范围的“命令与流程查找”，界面明确范围，不宣称跨项目全量搜索。不额外请求无权限数据，不缓存其他用户结果。若会影响主体工期，可列入 P2；原导航始终可用。

### 3.2 断点与可见面积

| CSS 视口宽度 | 布局规则 |
| --- | --- |
| ≥1440px | 完整顶栏；Inspector 默认 360px、最大 420px；试跑输入/输出 40%/60% |
| 1024–1439px | 次要顶栏动作进入更多菜单；Inspector 320px；Dock 保留撤销、重做、缩放、适应画布 |
| 768–1023px | 折叠侧导航；Inspector 覆盖宽度 `min(360px, 100%)`；试跑上下分区 |
| <768px | 列表与详情优先；Inspector 采用全宽模态面板；隐藏画布的重复工具但保留所有操作入口；不宣称完整触屏编排验收 |

使用 `100dvh` 与 flex/grid 的 `min-height: 0; min-width: 0` 管理工作区；不能依赖固定 `100vh - 56px` 推导所有页面。表格允许自身横向滚动，页面外壳不产生水平滚动条。

面积测量口径：可操作画布面积 = 画布矩形面积减去 Inspector、节点库、Dock、MiniMap 在其内部覆盖区域的并集面积。固定 1440×900、100% 缩放，分别测量面板关闭/打开状态，并与实施前同状态比较。目标是不回退；期望增益需附截图与计算，不预填 35% 或 88%。

### 3.3 设计器结构

```text
全局导航（48）
设计器工具栏（44）：返回 / 流程名 / 保存状态 / 保存 / 预检 / 发布 / 更多
┌─────────────────────────────────────────────────────────────┐
│ [+ 节点]                       画布区域                     │
│                                       ┌────────────────────┐│
│ 节点库按需覆盖在左侧                  │ 节点/连线属性      ││
│                                       │ 非模态 Inspector   ││
│                                       │ 独立纵向滚动       ││
│   [撤销 重做 | 整理 | 缩放 | 适应]     └────────────────────┘│
└─────────────────────────────────────────────────────────────┘
```

右侧面板覆盖画布，不参与画布宽度布局。Dock 水平居中于扣除 Inspector 后的可用宽度，距底部 16px；MiniMap 默认折叠，展开后避让 Dock。左右面板同时打开导致剩余宽度不足 480px 时，关闭节点库并保留显式重新打开入口；不能让所有悬浮层互相盖住。

### 3.4 整体界面重设计原则：先减负，再美化

本节是用户追加要求后的核心实施范围，优先级高于动效。必须重新安排布局、按钮和信息展示，不能只换颜色、圆角和行高后宣布完成。

源码已见的结构问题：流程列表默认同时展示 12 列；系统配置同时出现侧导航、单一活动 Tab 和内容标题；运行中心同时布置 5 个统计块和 420px 列表/详情分栏；仓库使用 300px/自适应/430px 三栏。这些设计在受限窗口中容易压缩主要任务区域。它们是源码结构观察，实际遮挡和首屏高度需由 UI-00 截图量化。

统一页面骨架采用“一个定位区、一个操作区、一个主要内容区”：

1. 定位区：面包屑只说明上级，当前页标题只出现一次；业务名称常驻一处，不在顶栏、侧栏、卡片内重复三遍。
2. 操作区：标题右侧放当前页面主动作；筛选只服务当前数据集；查看方式切换放在列表上沿，不与全局导航混排。
3. 内容区：让当前任务所需数据占据主体；记录详情按需打开，避免未选择记录就展示半屏空详情。
4. 说明文字：长期说明压缩为一行帮助入口；只对当前错误、权限限制和待处理事项显示提示，不在每页顶端堆蓝色提示卡。
5. 卡片：只有独立对象或有明确分组意义才用卡片；普通表单与列表用标题、留白和分隔线，不再“页面卡片 → 分区卡片 → 字段卡片”。

普通列表页横向 padding 24px（窄屏 16px），页标题区约 56–64px，筛选区默认一行约 44px。1280×800、100% 缩放下，普通列表首条记录建议在顶部 240px 内出现，至少完整看到 8 条普通行；200% 缩放时以可读和可达为优先，不强行压缩满足行数。

### 3.5 信息分层与数据展示规则

| 层级 | 用户要回答的问题 | 展示位置 | 示例 |
| --- | --- | --- | --- |
| L1 识别/决策 | 这是什么、现在怎样、我能做什么 | 列表、页面摘要，默认可见 | 名称、类型、当前状态、更新时间、主操作 |
| L2 解释/处理 | 为什么如此、下一步怎样处理 | 选中记录后的详情区/详情页 | 审批人、失败原因、输入摘要、发布记录 |
| L3 追溯/诊断 | 原始事实与技术细节是什么 | 详情内部的专属 Tab/展开区 | 完整 ID、JSON、事件、版本、诊断字段 |

字段不能只因后端返回就进入首屏。为每个页面建立“字段 → 数据来源 → L1/L2/L3 → 默认是否显示 → 无值语义”清单，保存在任务验证文档；移动到详情的字段必须有可达路径，不能删数据来制造清爽。

名称为可点击主标识，代号最多一行辅助说明；内部 UUID 默认不占列表整列，可在详情复制完整值。默认列数 5–7 列（含操作），审批等确有必要可例外但需写明。长说明最多两行，完整说明在详情中可选中复制，不能只提供不可访问的 title tooltip。

相对时间与精确时间分层：列表“10 分钟前”，焦点提示或详情显示带时区的完整日期时间；排序使用原始时间值。数值带单位和口径，未知值“—”，未配置“未配置”，加载中不能显示 0。JSON、长错误栈、资源 schema 不进入普通表格单元格。

统计卡不是页面标配。列表默认不显示统计卡；已有统计确实影响判断时，最多保留 3 项紧凑摘要或一行计数，并标明筛选范围/更新时间。没有可靠汇总数据则省略，不能从当前页推算全局统计。运行总览与处理待办可有不同摘要，但不在每个子页重复相同数字。

### 3.6 按钮体系与操作优先级

| 类别 | 视觉与位置 | 使用规则 |
| --- | --- | --- |
| 页面主动作 | 一个实色按钮，标题右侧 | 新建业务、新建流程、保存草稿等，每个活动操作区最多一个；弹窗有自己的提交区 |
| 直接辅助动作 | 描边/轻底按钮，主动作左侧 | 默认最多两个，如导入、预检；不要所有按钮同权重 |
| 低频动作 | “更多”菜单，按业务分组 | 导出、复制、历史、归档；原有能力必须仍可发现 |
| 行操作 | 1–2 个文字按钮 + 更多 | 详情可由名称进入；避免同时“名称链接 + 查看 + 详情”重复 |
| 危险动作 | 菜单末尾独立组、危险色 | 删除/取消发布等，确认文案包含对象和影响；不与主动作并排争抢注意力 |
| 图标动作 | 32px 点击区、可访问名称、tooltip | 仅用于通用符号如关闭/刷新；审核、发布等业务动作使用文字 |

普通列表不在每一行同时放“查看/设计/审核/发布/取消发布/发起/复制/删除”。由状态和权限决定主要入口：草稿以“设计”为主，已发布以“发起”为主，待审核且有审核权时在更多菜单提供明确“审核”项。禁止把“发起”统一改成“运行”而丢失原有业务语义。

设计器常态以“保存”为实色按钮，“预检”“发布”为描边/轻底动作；“试跑”在同组轻底按钮，窄屏优先把低频发布移入更多菜单。发布确认弹窗的“确认发布”成为该弹窗唯一主按钮。这样保留关键路径而不出现四个同色大按钮争夺视觉焦点。

菜单项使用明确动词和对象；不可用动作应显示可理解的原因（例如“审核通过后可发布”），无权获知的能力或对象可隐藏。不以“没有权限”的灰按钮泄漏受限对象信息。

批量操作只在已有后端能力且用户选中记录后出现，放到列表选择工具条；显示数量、退出选择入口与影响范围。原有批量审批必须保留；部分成功分别列明成功/失败，不清掉失败项。没有批量契约时不新造批量按钮。

### 3.7 页面逐项布局规格

#### A. 业务中心与业务内流程列表

业务中心默认列表，不用多个大卡片排列业务名称与重复指标。页面标题“业务中心”，右侧“新建业务”，导入为辅助、下载模板在导入附近菜单中。默认列：业务名称/代号、说明、可见范围摘要、更新时间（仅数据源有此字段时）、操作。成员明细、完整部门列表和审计信息在详情/成员页中显示；超长可见范围用“部门 3 / 人员 5”及详情入口，计数需有真实字段支持。

业务内采用 200px 侧导航（流程/成员/资源/服务端点），可折叠至 56px；不再重复放大幅“当前业务”介绍卡。内容区标题“流程”，筛选行保留名称、类型，审核/发布状态放“更多筛选”，有条件生效时在下一行显示可移除条件摘要。重置只清空筛选，不清空用户列偏好。

流程列表默认列及建议宽度：名称/代号 `minmax(220px,1fr)`、类型 88px、审核 104px、发布 96px、更新时间 136px、操作 176px。代号并入名称单元格以降低默认横向压力；独立代号列为用户可选。名称可换行，其他关键字段不被压成逐字竖排。宽度是起始值，按实际容器调节；默认模式不强制 1400px。详细模式可横向滚动。

业务侧栏 │ 流程                                      [新建流程] [更多]
         │ [名称搜索____________] [类型▾] [更多筛选] [查询] [重置]
         │ 生效条件：待审核 ×                              [列设置]

         │ 采购审批      状态流   待审核   未发布   10分前    设计 ···
         │ ORDER_FLOW

#### B. 流程设计器

设计器打开后进入专用工作区，收起业务侧栏，面包屑返回原项目列表并恢复筛选与滚动位置。工具栏只放当前流程相关动作；版本/审核/发布的详细记录进入“流程信息”，不能全部堆在节点画布上方。

节点库按流程类型展示可用节点，默认关闭，由左上“添加节点”打开；节点类别可折叠，支持名称搜索，拖拽和点击添加均需保留。模板/子流程作为库内分类，不额外常驻整排卡片。节点标题两行以内，摘要只保留决定连线/配置判断的 1–2 项；完整参与人、表达式、输入输出字段在 Inspector。

Inspector 顶部固定“节点名 + 类型 + 关闭”，其下分组表单，底部只显示当前配置的校验摘要；不要在每个分组重复一个“保存”按钮。字段变更进入流程草稿，由顶栏统一保存；若原字段有独立提交语义则明确标注，不能悄悄改为自动提交。

#### C. 流程详情与版本查看

首屏只显示名称、类型、审核/发布状态、最近更新时间；右侧按权限显示“进入设计”或“只读查看”，次要动作进更多。正文分“流程图 / 基本信息 / 已有发布或运行记录”几个真实数据支持的视图。默认流程图不再上下重复显示一份完整字段表；切换基本信息时使用两列标签值布局，长描述单独整行。无版本历史接口时不创造时间线。

#### D. 已启动流程、待办与运行观察

保留“待办处理”和“运行观察”的业务区别：待办服务审批人，运行观察服务查看实例执行者。不得为统一界面将待审批状态映射成引擎运行成功/失败。

入口默认展示当前已有的工作台视图；不同视图的原能力如看板、列表、日历放在同一“视图”切换中，不同时把看板统计、实例详情和任务操作铺满页面。待办列表默认列：事项/流程、当前环节、发起人、到达/截止时间、状态、处理；审批意见、会签进度与业务字段在点击处理后展开。

运行列表默认列：流程/实例标识摘要、类型、运行状态、开始时间、耗时/等待时长、查看。运行详情按需打开：≥1440px 可用左侧 360px 列表 + 右侧详情；较窄窗口进入独立详情面，返回恢复选中项和滚动。没有选中实例时列表占满主区，不常驻“请选择”的大空白面板。

详情上方保留“状态 + 关键时间 + 当前等待/失败原因”，正文依次是业务结果、执行记录、技术详情。审批操作固定于处理面板底部，“通过”主按钮、“驳回”危险描边，其他原有动作进入更多；动作前显示对象、意见要求，提交中锁定同一处理任务。不能把业务同意/驳回设计成没有文字的图标。

#### E. 流程仓库

取消默认三栏同时展开。默认“筛选 + 条目列表”，条目展示名称、流程类型、可用版本/状态（已有字段）、更新时间。上传/导入为当前流程对应主操作，二者语义不能合并错：按实际入口和契约命名。

选择条目后才打开右侧详情；宽屏详情 400px，窄屏进入独立详情。详情内先概要与可执行导入动作，原始定义/JSON 放折叠区。可恢复归档流程进入明确的“归档”视图，不能在活跃仓库列表上方长篇平铺。恢复与导入保留原有差异及确认流程。

#### F. 资源与服务端点

优先列表→详情/编辑：默认展示名称、资源类型、状态、所属范围、更新时间（已有时）、操作；不把完整连接串、schema、请求头放进列表。编辑采用“基础配置 / 连接与认证 / 高级选项”渐进展开，必填基础项默认展开，字段错误自动打开所在分组。

密钥仅使用当前允许的引用/掩码，保持既有脱敏规则；复制功能不能意外复制真实凭证。只有已有检测接口时才显示“测试连接”，无接口不做假成功按钮。说明、帮助和实例占位不代替实际标签。

#### G. 系统配置、组织与权限

系统配置保留左侧 200px 分类导航，右侧直接显示当前页标题与内容，删除重复的“单项活动 Tab”装饰结构；移除后同步恢复正确标题/区域语义。一般表单内容最大宽 880px，表格可铺满；标签上置，相关字段 1–2 列，复杂长输入整行。

组织页使用组织树 + 当前组织内容，树默认 240px，可折叠；成员与角色属于内容内部的功能切换，不叠加另一层大型横向导航。授权界面突出“对象、授权范围、角色、继承来源”，详细权限按需展开；不把所有权限点做成首屏大量彩色标签。

运行诊断页先显示服务可用状态/异常摘要，再显示构建与 Worker 详情；镜像 digest、SHA、迁移字段用可复制信息表，能力集合用分组列表替代每项一个大卡片。状态必须来自真实接口，不因颜色变绿就视为健康。

### 3.8 布局重构验收：解决粗糙与堆积的硬门槛

- 每页首屏有明确的当前对象、主要状态和主动作；标题不重复，操作分组不重复。
- 普通列表默认 5–7 列，完整字段存在明确的详细模式/详情入口；内部 UUID、JSON、错误栈不占普通首屏主区域。
- 页面级操作区最多一个实色主按钮、两个直接辅助动作；行操作最多两个直接动作，危险操作独立分组。
- 首屏不叠加多层说明卡、统计卡、筛选卡；无业务必要的计数移到紧凑摘要，现有统计能力仍可在对应概览查看。
- “记录未选中”“面板关闭”的主内容区域能回收，不留下大面积固定空栏。
- 1280×800 下普通列表达到第 3.4 节信息可见目标；设计器以画布为主体，不被模板卡、信息条和工具条挤成狭缝。
- 每个页面提供实施前后同尺寸截图，逐项标注移走了什么、移到哪里、哪个主要任务变短；不得只展示一个漂亮的空数据截图。
- 截图样例同时含长名称、长中文说明、无值、错误、不同权限和至少 20 条列表数据；检查真实内容密度，而非仅检查空白布局。

## 4. 设计系统与迁移规范

### 4.1 语义 Token

继续使用现有 `--background`、`--foreground`、`--primary`、`--border` 等语义名，经 `@theme inline` 映射到 Tailwind；禁止新增一套冲突的根级 `--color-primary` 覆盖映射。建议值如下，最终以实际对比度检查为准。

| --- | --- | --- | --- |
| `--background` | `#fcfcfd` | `#17191d` | 应用底色 |
| `--foreground` | `#18191b` | `#f2f3f5` | 主要文本 |
| `--card` / `--popover` | `#ffffff` | `#21242a` | 面板/浮层 |
| `--card-foreground` / `--popover-foreground` | `#18191b` | `#f2f3f5` | 面板文本 |
| `--muted` / `--secondary` / `--accent` | `#f1f3f5` | `#2b3038` | 次级表面、hover |
| `--muted-foreground` | `#5c6370` | `#b7bec9` | 说明、时间戳 |
| `--secondary-foreground` / `--accent-foreground` | `#18191b` | `#f2f3f5` | 次级动作文本 |
| `--primary` | `#1e2229` | `#e4e7ec` | 主动作背景 |
| `--primary-foreground` | `#ffffff` | `#17191d` | 主动作文本 |
| `--border` | `#e2e5e9` | `#414854` | 装饰/分隔边框 |

sidebar 对应变量映射到同主题表面、文本、边框和主动作色；图表保留多序列辨识能力，不能把 chart 全部改为灰色。禁用态保留可读名称与原因，不单纯用低 opacity 淡化全部内容。

普通正文与背景至少 4.5:1，重要控件边界/状态图形至少 3:1；浅灰装饰分隔线不能成为唯一控件边界。状态始终用“图标 + 中文文字”，类型也保留文字，不能只靠色点传达。标准参考：[WCAG 2.2](https://www.w3.org/TR/WCAG22/)。

### 4.2 字体、尺寸与层级

- 中文字体：`"Segoe UI", "Microsoft YaHei UI", "Microsoft YaHei", "PingFang SC", system-ui, sans-serif`；代码：`ui-monospace, Consolas, "Cascadia Code", monospace`。不新增远程字体加载依赖。
- 正文/输入 14px、紧凑表格 13px、辅助文字 12px、标题 18–20px；行高正文 1.5，长中文说明可换行。11px 仅用于非关键快捷键提示。
- 间距基准 4/8/12/16/24px；按钮默认高 32px，表单控件 36px，图标按钮点击区至少 32×32px；触屏优先 44px。表格单行默认 40px，双行 56px，不裁断文字以强制行高。
- 常规圆角 6px，面板/弹窗 8px；只给浮层阴影，不依赖全局 `.rounded-*`、`.shadow-*` 覆盖强制改所有组件。
- 数字列使用 `tabular-nums`，数值右对齐，时间保留精确值提示；空值为“—”，不能把 0 当作空值。
- 层级约定：画布图元由 React Flow 管理；画布工具 20、Inspector 30、全局导航 40、菜单 50、模态遮罩 60、模态内容 70、toast 80、skip link 100。实现时验证 Portal stacking context；模态内部菜单必须在模态上方，并受同一模态交互边界管理。

### 4.3 CSS 迁移次序

先建立语义 Token → 迁移共享 Button/Input/Table → 迁移具体页面的硬编码颜色 → 删除已被替代的局部覆盖。每批同时验证 light/dark，不强行清空旧规则。保留业务相关隐藏/展示选择器，除非本批明确完成对应逻辑替换。新增样式限定在组件或 `data-aiflow-*` 范围，不对所有 SVG、button 或 `.react-flow__node` 加泛化动画。

## 5. 业务状态和交互契约

### 5.1 通用状态矩阵

| 状态 | 必须呈现 | 允许动作 / 数据保护 |
| --- | --- | --- |
| 首次加载 | 固定几何尺寸骨架、加载文案、`aria-busy` | 不把未返回数据显示为“暂无记录” |
| 空数据 | 区分没有记录与筛选无结果 | 有权限者可新建；筛选无结果提供清空条件 |
| 后台刷新 | 保留旧数据，显示轻量刷新状态 | 不卸载表格、不清空当前选择 |
| 请求失败 | 就地错误与重试；已有数据标记可能过期 | 表单值、筛选条件、滚动位置保留 |
| 提交中 | 按钮保留宽度，显示具体动作，如“保存中” | 禁止同一动作重复提交；不禁用无关浏览操作 |
| 无权限/只读 | 明确只读原因和可用查看入口 | 界面限制加既有服务端权限校验；快捷键和事件也遵守 |
| 会话过期 | 提示重新登录 | 不自动重放发布/运行等写请求；保留当前内存草稿，不持久化敏感输入 |
| 未知服务端状态 | 显示“未知状态”及可查看的原值 | 不默认为成功，不提供依赖成功状态的动作 |

### 5.2 保存、离开、发布

保存状态独立于审核状态与发布状态：`clean → dirty → saving → clean/error`。使用本地编辑 revision 与本次提交 snapshot 比较：保存期间继续编辑时，旧请求成功不能把新修改标为已保存。失败保留 dirty；只有服务端成功才能显示保存时间。

同一流程最多一个保存请求在途；`Ctrl+S` 与按钮复用同一动作。切换流程/业务、返回列表时，dirty 状态提供“保存并离开 / 放弃修改 / 继续编辑”；保存失败停留原位置。刷新/关闭页面使用浏览器 `beforeunload` 能力，不承诺自定义弹窗；无 dirty 时不阻拦。

发布复用既有审核与权限规则。若发布前需要保存，必须等待保存成功；预检复用 `workflow.compile` 及现有诊断语义，预检通过不等于发布成功。发布确认中展示流程名和当前已知版本；没有后端版本字段时不虚构编号。发布失败保留可重试信息，审核状态 `init/approved/rejected` 与发布状态 `draft/published` 分列显示。

没有服务端乐观锁证据时，不宣称“已解决多用户编辑冲突”。若收到冲突错误，保留本地修改并提示刷新比较；版本控制升级作为单独任务。

### 5.3 列表与表格

`ProcessCenter` 默认 6 列：名称/代号、类型、审核状态、发布状态、更新时间、操作；说明摘要和独立代号列为可选，完整说明可在详情读取。数据源、创建人、创建/发布/取消发布时间进入“列设置”或详情，不能删除其可达入口。详细模式继续支持原字段，列偏好按用户/项目作用域隔离；存储不可用时回退默认。

操作列默认 176px、实色背景，表头和行保持同一 sticky 宽度；hover/selected 背景同步。常驻“设计/查看”“发起”，次要操作进入更多菜单；权限不足不能凭空变为可编辑。发布、取消发布、审核、详情等仍遵守原业务条件。行点击不能吞掉按钮事件；表格保留原生 table 语义，未实现 grid 键盘协议时不设置 `role=grid`。

保留当前“编辑筛选条件 → 查询应用”语义。若后续改为即时搜索，必须同步处理防抖、请求竞态与分页，不在同页混用两种交互。状态 Tab 的计数仅来自已知数据范围，不能把当前页长度当全量总数。分页、排序只提供现有数据能准确支持的范围；不伪造服务端分页。

## 6. 画布专项规格

### 6.1 节点与面板

节点保留既有种类图标、标题、端口 ID、连接方向和业务提示。类型侧线表示流程类型；配置完整度与运行状态必须分别标识，不能用同一个灯同时表示“已配置”和“运行成功”。选中用 2px 轮廓，不平移外层节点，不改变端口相对位置。hover 仅改变内部表面；错误节点显示可读错误摘要。

Inspector 桌面为非模态 `aside`，有名称和关闭按钮，不设焦点陷阱、不让画布 inert。点击节点打开时不抢走画布焦点；显式“编辑属性”动作可聚焦首字段。面板内 Escape 关闭后返回选中节点，节点已删除则回到画布工具栏。窄屏模态版本使用现有 Radix Dialog 焦点管理，关闭后恢复触发位置。

属性字段继续使用既有配置契约，分为基本信息、业务配置、路由/输出、高级设置；根据节点能力显示，不给每种节点强塞审批字段。错误字段所在分组自动展开并定位。切换节点时，已合法的本地修改写入画布草稿；存在未提交的无效字段时提示“修正 / 放弃本次字段编辑”，不能静默丢弃。

保留现有 normal/compact/maximized 和锁定能力的等价入口。多选显示数量与已有批量能力；边选择显示边属性；空白点击清除选择并收起 Inspector，但固定/锁定模式遵循明确按钮语义。锁定只限制属性编辑，不混同流程全局 readOnly。

面板开关不得自动 fitView。选中节点被面板遮挡时提供“定位节点”，必要时将其平移到未遮挡区域；用户拖动/缩放时不自动抢回视口。

### 6.2 保留的操作和快捷键

| 操作 | 行为与保护 |
| --- | --- |
| 拖拽/框选/Ctrl 多选/右键菜单 | 保持现有行为，工具浮层不得截获画布空白区域事件 |
| 删除 | 只在画布焦点范围、可编辑且无输入法组合时生效；保护开始/结束等现有不可删节点 |
| Ctrl+Z / Ctrl+Shift+Z / Ctrl+Y | 画布拥有焦点时操作图历史；文本输入时交给原生撤销 |
| Ctrl+S | 当前流程可编辑时保存；避免浏览器另存为；输入法组合中不触发 |
| Escape | 先处理最上层菜单/弹窗，再处理面板；一次按键仅关闭一层 |
| Ctrl+Enter | 仅试跑弹窗中、输入合法且未提交时运行；不劫持普通多行编辑 |
| F11/全屏按钮 | 不覆盖浏览器自身 F11；按钮复用既有全屏 API，拒绝时显示错误 |

Windows 显示 Ctrl，Mac 根据平台显示 Cmd。全局监听必须有清理函数，按活动流程/画布作用域路由；现有 `flow:neaten-canvas` 等事件要在处理器中验证 readOnly，不能只禁用按钮。面板卸载、流程切换后不得留下旧监听。

### 6.3 连线反馈

连接合法性唯一复用 `canConnectCanvasNodes` 及既有校验，不在动画中复制一套规则。合法目标端口可显示轮廓与简短提示；非法目标显示原因，释放后不生成边、不写历史。重复边、环、跨类型限制以当前业务规则为准，不能为视觉效果放宽。

视觉端口可小于点击区，但命中区域建议至少 24×24 CSS px，不能因放大 transform 改变锚点。若增加 24px 接近提示，按屏幕坐标计算并测试不同 zoom，提示半径不等于放宽真实连接规则。连线成功仅闪现一次短高亮；减少动态效果时只显示稳定的选中态。不以每条边持续流光表示执行状态。

### 6.4 自动整理：正确性先于动画

继续使用当前 `autoLayoutNodes`。不安装 ELK/Dagre 来完成本轮视觉目标；算法更换另立需求。React Flow 的节点位置属于图状态，不能只给 DOM transform 加 transition，否则容易出现边先跳到终点、节点仍在移动的不同步。[React Flow Node 类型](https://reactflow.dev/api-reference/types/node)说明了位置数据的归属。

实施流程：

1. 校验当前作用域及 readOnly；结束正在进行的拖拽后才可启动。捕获起点快照，只记录一次历史。
2. 计算目标坐标，保留全部 ID、data、handles、edges、选择和业务配置；只更新 position。
3. 对小图通过 `requestAnimationFrame` 插值受控节点位置，使连线随相同位置状态更新。中间帧不得触发自动保存、定义持久化或多次历史入栈；需为现有 change effect 增加事务边界。
4. 正常结束时一次提交最终定义，再依据最新节点 bounds 执行视口适应；不得依赖固定 50ms timeout 猜测渲染完成。
5. 用户开始拖拽/缩放时结束动画到目标坐标、完成本次事务，再接受新操作；取消待执行的 fitView，避免争夺控制。再次点击整理不排队。
6. 流程切换/卸载清理 RAF 与延迟回调，并用流程 ID/操作代数拒绝过期写入。旧动画不得写入新流程。
7. 减少动态效果或节点超过 100 个/边超过 200 条时，默认直接提交终点；此阈值为初始工程策略，可按性能证据下调，不是容量承诺。

验收必须包括整理 → 撤销 → 重做坐标一致；保存后重开坐标一致；动画中节点与边连接不脱节；只读状态通过按钮、快捷键和自定义事件都不能整理。

## 7. 动效规范与降级

本轮不引入 CSS `linear()`、无限弹簧或全局布局动画。CSS 用于局部反馈；Framer Motion 仅在确有跨状态布局收益的导航指示器/浮层中按需使用。

| 触点 | 时长 / 属性 | 限制 |
| --- | --- | --- |
| 按钮 | 100–120ms，背景/内部 scale 最多 0.98 | disabled、pending 不重复弹跳；不影响点击区域 |
| Tooltip/菜单 | 入场 160ms，退出 100ms，opacity + 最多 4px 位移 | Tooltip 延迟约 400ms；键盘聚焦可读，包含必要说明的内容不能仅 hover 可见 |
| 局部 Tab 指示 | 180ms，transform/opacity | 每个容器独立 LayoutGroup/layoutId；避免跨页面错误共享 |
| Inspector | 入场 220ms、退出 160ms，translateX/opacity | 不使用 backdrop blur；退出后不可聚焦不可点击 |
| 模态 | 入场 180ms、退出 120ms，opacity + scale 0.98→1 | 内容立即可用；焦点处理交给 Dialog |
| 整理 | 280ms，节点坐标插值 | 按第 6.4 节事务与降级执行 |
| 视口定位 | 180–250ms | 用户操作可打断；减少动态效果时 duration=0 |
| 新结果 | 最多 120ms 淡入 | 不延迟真实数据展示，不对整张表 stagger |

统一缓出曲线 `cubic-bezier(0.16, 1, 0.3, 1)`，不称其为真实物理弹簧。避免 `transition: all`、对整页 width/height 动画、永久 `will-change`、全屏模糊。短动画完成后释放临时合成提示。运行标识默认静态图标与文字，避免几十个节点持续呼吸。

建立统一 `useMotionPreference`（建议新文件）读取并监听 `prefers-reduced-motion`，供 CSS、Framer Motion、RAF 和 React Flow fitView 共用。减少动态效果时取消位移、缩放、自动滚动和脉冲，允许 ≤80ms 的透明度反馈；状态文字与进度信息仍保留。不能仅写 CSS 媒体查询而漏掉 JS 驱动动画，也不能依赖 animationend 才完成业务动作。

## 8. 试跑与运行观察

### 8.1 双栏布局

宽屏弹窗 `width: min(1200px, calc(100vw - 32px))`，最大高度 `calc(100dvh - 32px)`；固定标题与底部动作，中部左右各一个滚动区域。左栏输入字段/JSON、输入错误；右栏“结果 / 执行记录 / 输入快照”，保留现有表格预览、分页与 JSON 能力。窄屏改上下布局，避免正文再套多个滚动容器。

左栏展示当前编辑输入，右栏展示该 run 的不可变输入快照，二者不可混淆。运行后继续改输入不改变历史快照。JSON 复制保留原值并处理剪贴板失败；大结果复用现有分页，禁止一次格式化未知大小的全量数据阻塞界面。

### 8.2 执行真实性

当前调用的是实际执行接口，`triggerType: test` 不自动意味着无副作用。标题采用“流程试跑”，操作附近说明“将保存草稿并发起执行，实际影响由流程配置决定”。不要称为隔离沙箱或无副作用仿真。测试验收使用专用项目和可控数据。

前端请求阶段与后端运行状态分离：`idle / saving / submitting / observing / requestError` 是 UI 阶段；执行成功、失败、排队、等待等来自实际接口。HTTP 请求成功仅表示请求结果已返回，不等于流程全部成功；人工审批等待不归为失败。未知状态按通用矩阵显示。

必须保持 `onSaveDraft → workflow.run/data.run` 次序，保存失败不发起运行。同次点击只发起一次请求；存在幂等契约的路径复用同一逻辑尝试 key，显式“再次运行”才是新尝试。不要给尚不支持幂等参数的数据流接口擅自增加字段。响应丢失时不能无提示自动重发可能有副作用的请求。

执行列表按服务端事件时间/序号及现有稳定标识组织；节点重复执行需保留 attempt，不按 nodeId 去重丢掉重试。并行步骤不人为串行点亮；没有时间信息时保持接口顺序并注明排序依据，不用动画生成虚假耗时。

轮询失败显示“状态更新暂不可用”，保留最后已知状态，不改成执行失败。runId、workflowId 变化时清理旧请求/订阅，忽略过期回包；关闭弹窗只关闭观察，不等于停止执行。未有取消接口时不展示“停止运行”。重新打开的恢复行为以现有运行查询为基础，不能在 remount 时重新提交。

### 11.3 性能测量

不得为性能验收关闭业务校验或减少样例边数；与实施前同环境比较，既有瓶颈单独列出。动画不应额外等待网络、阻塞保存或延迟错误反馈。
