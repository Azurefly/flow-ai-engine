## 3. 架构判断

### 3.1 前端

- `client/src/pages/Home.tsx` 同时承担 Hash 路由、选中项目/流程、草稿状态、运行入口和多个业务模块编排，是全局状态和交互契约的主要汇聚点。
- `WorkflowCanvas.tsx` 使用 React Flow 管理节点/边，并将完整定义回传父级；路由、撤销、局部配置与父级草稿之间存在较强耦合。
- `WorkflowGovernance`、`RunCenter`、`DataResourceCenter`、`ProcessWorkbench` 以项目或流程 ID 查询数据，但多个组件没有把 loading/error/empty 明确区分，且大量使用 `any`，降低了契约变更时的编译保护。
- 自定义 `CreationDialog` 和任务抽屉未完整继承现有 Radix 可访问性能力；流程节点键盘操作和焦点管理仍不完整。

### 3.2 后端

- Express 入口统一挂载请求关联、安全头、来源校验、健康检查、OAuth、定时回调与 tRPC；HTTP 服务启动后拉起持久化 workflow worker。
- 工作流运行通过数据库 job、租约和 worker 执行，已具备明显优于“请求内同步执行”的恢复骨架。
- 授权分布在 tRPC 中间件、IAM、项目、流程和任务服务中；多数 mutation 有服务端校验，但少数关键状态在事务外检查，存在 TOCTOU。
- MySQL 访问以 `mysql2` SQL 为主；部分跨数据库与外部调度服务的操作缺少 outbox/saga 和幂等补偿。

## 5. 其他重要风险

- OAuth 回调写入 `app_session_id`，tRPC context 读取 `flow_session`。如果 OAuth 是正式入口，需要立刻验证并统一会话；否则 OAuth 登录后可能仍无法调用受保护业务 API。
- 数据源连接配置的敏感字段过滤依赖有限关键词和顶层删除，建议改为白名单 schema 并递归清理。
- 写请求缺少 Origin 时当前可放行；结合 cookie 策略，应为 cookie 鉴权 mutation 增加严格 Origin 或 CSRF token。
- 定时回调会把原始内部错误 message 返回调用方；外部 fetch 也缺少统一超时、响应大小和有限重试封装。
- 生产端口冲突时服务会静默寻找其他端口，可能导致反向代理和健康检查仍指向错误端口。
- 多个列表接口没有分页；随着运行、任务、用户和流程增长，会形成延迟与响应体风险。
- 画布、Home 和 ProjectWorkspace 文件体积和职责过大；总 bundle 已使用门禁的约 89.6%，应继续按页面和编辑器能力拆分。

## 6. 本轮整改范围

第一批采用“数据正确性和安全优先”的策略，目标是关闭以下可独立验证的问题：

1. 修复数据源 `credentialRef` 契约和数据流运行输入执行语义，并增加 round-trip/执行测试。
2. 修复 workflow 回滚审批绕过、启动事务内状态复核、service semaphore permit 计数，并增加测试。
3. 修复跨流程治理状态泄露、生产错误边界堆栈泄露和资源删除确认/防重复提交。
4. 引入定义版本 CAS，阻止旧草稿静默覆盖新版本；前端提供明确冲突反馈并补充并发测试。

## 11. 集成门禁补强

服务器隔离预检暴露出一组此前被共享数据库、生产环境变量和旧夹具掩盖的问题。本轮没有删除或弱化故障注入、安全校验与持久化 Worker，而是修正契约和测试隔离：

- operate 节点缺省 `assigneeMode` 时，若存在内部用户或动态模板引用，按 `user` 推断；显式 `receivers` 保持权威，避免默认值覆盖旧定义；
- state/operate 的 `nodeDh` 与 `stateCode`/`commandCode` 别名按有效值保真，状态代号重复检查不再被占位默认值遮蔽；
- 顺序 operate→operate 成为合法控制流连接，并增加编译回归测试；
- 项目流程在创建数据库记录前验证 definition，非法草稿不再遗留孤儿 workflow；
- 私有子流程显式携带 `state`/`control` profile，父子流程的节点类型约束保持一致；
- durable command 测试辅助逻辑同时识别 `running` 和 `waiting`，人工任务创建后不再误等 10 秒；
- 组织角色默认生效时间由数据库 `NOW()` 生成，消除应用与数据库时间精度差造成的短暂“未来生效”；
- MySQL 集成文件关闭文件级并行，避免共享真实数据库、Worker drain 和进程级 fault switch 互相抢占；每个套件补齐独立用户、完整外键清理和确定性审计过滤。
- 固定公网 IP 的 HTTP 请求 lookup 同时兼容 Node 的单地址和 `all` 回调签名，保留 DNS rebinding/SSRF 防护，并以独立回归测试覆盖。

服务器预检严格使用 `NODE_ENV=test`、关闭后台 Worker 自动轮询，并接入独立数据库和前后端网络；预检完成后测试容器与数据库由清理钩子删除，未切换或复用生产业务数据。OAuth 未配置的警告符合当前环境现状，相关内部鉴权、账号中心和权限集成测试仍全部通过。
