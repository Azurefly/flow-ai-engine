# Flow AI Engine 线上界面逐页评审与实施补充方案

- 文档版本：追加方案 v1.0
- 检查日期：2026-09-25
- 基础方案：[整体界面、信息架构与交互动效重构实施方案 v3.1](./flow-ai-engine-ui-motion-redesign-proposal-2026.md)
- 目标：将登录后实际看到的布局、数据密度和按钮问题转成可以分批交给 AI 开发者实施的页面规格与验收要求。
- 优先级说明：本文的现场问题和修改规格补充基础方案第 3.4–3.8、8、9、10、11 节；若两份文档对现场布局的描述不一致，以本文实测结果及对应页面规格为准。流程定义、权限、审批、资源、安全和运行契约仍以基础方案为准。

## 1. 审查结论

现有问题主要是版面和信息架构把“所有字段、所有按钮、所有详情”同时放在首屏。业务列表与流程表格横向过宽；设计器上方多排节点、画布工具和复用流程挤占画布；详情与仓库默认保留没有选中内容的空白面板；管理页重复展示标题、统计和对象信息。结果是用户要横向找字段、竖向滚动找主内容，且主次操作难以区分。

本次修改应先重排页面结构和信息优先级，再迁移设计 Token 与动效。只调整颜色、圆角、字号或间距，不算完成。基础方案已有的 5–7 列规则、一个页面主动作、按需打开详情、画布优先、保存/发布/执行契约保护均保留；本文进一步指定实测页面中哪些字段要移动、按钮如何归组、空状态如何收缩，以及哪些提示必须与后端实际行为一致。

## 2. 审查范围与证据边界

### 2.1 检查方式

- 目标站点：用户提供并已登录的 Flow AI Flow Engine 页面。密码由用户在浏览器内输入，未读取或记录密码。
- 检查时间：2026-09-25；只读浏览已有数据和页面结构。没有创建、编辑、删除、导入、审核、审批、发布、取消发布、测试连接、发起流程或运行仿真。
- 主要检查桌面视口 1440×900；补查数据流程设计器、资源配置和端点目录时，嵌入浏览器实际视口为 681×900。窄视口表现作为问题证据之一，不替代后续在 1440×900、1280×800、768px 和 390px 的实施验收。
- 远端版本标识没有与本地 Git 修订建立对应关系。以下现场观察只代表该访问地址在检查时返回的界面；源码路径只用于本地实施定位，不能据此推断远端正在运行同一提交。
- 为避免暴露账号与项目数据，本文不复写具体人员身份、项目名称、内部 UUID、运行标识、密钥和完整业务说明。

### 2.3 本地源码交叉核对

本地工作区的可定位入口包括：ProjectWorkspace.tsx 中的 BusinessCenter、ProjectWorkspace、ProcessCenter 与项目服务端点；WorkflowCanvas.tsx；WorkflowDetailPage.tsx；WorkflowTestRunModal.tsx；ProcessWorkbench.tsx；RunCenter.tsx；WorkflowWarehouse.tsx；DataResourceCenter.tsx；SystemConfigShell.tsx；OrganizationManagementPage.tsx；Home.tsx。

本地 WorkflowTestRunModal.tsx 的按钮处理先等待 onSaveDraft，再按流程类型调用 workflow.run 或 data.run；状态/控制流程请求包含 triggerType=test，数据流请求调用 data.run。界面文案同时出现“沙箱”“仿真推演”“保存画布草稿”等表述。该源码交叉核对无法证明远端所部署版本相同，也无法单独证明后端隔离语义；因此本文要求先把运行语义查实，再调整产品文案，禁止只凭“test”字段断言它是隔离沙箱。

## 4. 可直接实现的关键页面结构

### 4.1 业务中心

    业务中心                                      [新增业务]
    [搜索名称/代号________________] [更多筛选]     [查询] [重置]
    业务名称（代号） | 流程数 | 工作域 | 创建时间 | 操作
    采购申请中心     |  12    | 采购域 | 9月17日  | 进入

- 下载模板归入导入菜单或导入旁的次要操作；导入为辅助动作。未配置 BDP 时同步入口保留可理解的禁用原因，必要时移到更多操作。
- 日期区间为低频条件时放入更多筛选，默认不占一行宽度。
- 业务总数、当前筛选结果数要区分；如果分页总数来自接口，放在列表页脚，不做大统计卡。
- 业务详情承接完整说明、根部门/工作域全值、创建人、审计信息与其他低频字段。

### 4.2 项目流程中心

    面包屑 / 业务名称                         [上传仓库] [新增流程]
    流程
    [搜索名称/代号________] [流程类型▾] [更多筛选] [查询] [重置]
    名称 / 代号          类型   审核       发布       更新      操作
    企业报销流程         状态   审核通过   已发布     10分前    发起  更多
    FLOW_EXPENSE_01

- “审批记录”不是选择某个流程的装饰性下拉；将其放到实际可查阅审批记录的位置，或明确为流程级审核记录入口并显示所选流程上下文。
- 新建为主动作，上传仓库为辅助动作。未授权操作不显示；可显示但不可用的已有动作必须解释缺少的前置条件。
- 行操作按状态映射：草稿/未发布以设计或详情为主；已发布以发起为主；待审且具审核权时提供审核入口；取消发布、删除等低频或有影响操作进入更多并保留确认。
- 任何字段移动都要保证在详情中可读、可搜索或可复制，不因默认隐藏而失去管理能力。

                                                └──────────────┘

- 详情页首屏先给流程图和当前状态；基本信息、实例列表和版本快照进入对应分区。用户切换视图后保留返回路径。
- 编辑器保存状态和权限/版本提示紧邻流程名；保存仅在草稿可编辑时主显。已发布流程不可改草稿时显示明确说明和原有“创建新版本/另存副本”入口。
- 节点库可通过搜索“名称、类型、用途”过滤，只列当前流程允许的节点；点击添加和拖拽行为均保留。使用分组折叠，不把所有类型平铺成按钮墙。
- Inspector 仅选择节点/连线后展开。分组内字段按最常用配置顺序；复杂映射、兼容字段和原始值折叠但可到达。错误定位时自动展开对应组并滚动到字段。
- 只读模式不出现禁用的添加控件；用明确的“只读”状态替代整排灰色按钮。
- 画布工具提供可见文字或可访问名称，常用操作 32px 以上点击区，保留现有键盘快捷键、撤销/重做、连线、选择、自动布局和焦点行为。

### 4.4 已启动流程与运行监控

- 工作台首屏以待处理列表或用户所选看板为中心。左侧数字成为紧凑徽标；摘要数值点击后必须到达口径一致的过滤列表。
- 待办无记录时显示“当前没有待处理事项”，保留搜索/筛选入口；批量意见框与批量决定动作仅在至少一项选中后出现。
- 处理详情按“当前任务与状态 → 业务表单 → 处理意见 → 处理动作”排列。底部固定原有同意/驳回/转办/领取等真实权限动作；提交期间锁定该任务，失败保留已填内容。
- 运行监控使用单行主筛选；用户筛选提供姓名或可读标识搜索，不能要求用户记忆内部 User ID。高级条件折叠。
- 没有选中运行时不要分配一半宽度给“请选择”；选中后再开详情侧栏。失败原因置顶，节点轨迹、业务结果和技术诊断分层显示，不把完整日志堆入摘要。
- “失败告警”严格根据真实告警数据渲染；零条时用轻量状态行。统计的时间范围、过滤范围和更新时间始终可见。

### 4.5 流程仓库、资源和端点

- 仓库默认目录树 + 列表，不常驻第三栏。选中条目后右侧只显示名称、类型、版本、时间、说明和原有动作；画布需单独打开大尺寸只读预览。
- 数据源列表继续只展示名称、类型、状态、最近校验。凭据/连接元数据只读且脱敏；任何密钥都不复制到详情提示或日志。
- 资源探查列表显示名称、数据源、字段数/样本行数、状态；字段详情与样本采用按需查看。
- UDF 页面为空时沿用“已审核 UDF 才能被数据流引用”的现有安全说明，提供唯一注册入口；不添加任意代码执行入口。
- 服务端点列表展示名称、允许地址、认证类型和状态；未配置时把“HTTP/REST 节点不能发布”与“新增端点”放在同一空状态内。
- 对连接测试、资源探查或运行操作先呈现影响范围与进度；具体副作用按现有 API 合约，不在布局重构中扩大权限。

### 4.6 系统配置、组织与权限

- 系统配置左侧分组导航继续保留，右侧每次只显示一个页面标题和一个内容主区。常规设置不同时显示重复只读值卡与同值编辑表单。
- 组织树和账号/成员表格可并列；窄屏先显示所选对象，再切换到详情。当前组织名称和路径只作为一处标题，完整路径放详情，不让表格行重复三段路径。
- 新增部门菜单要根据选中树节点解释相对层级。删除和停用须危险分组、明确对象和影响、二次确认，且保留既有权限。
- 账号、角色、授权范围和权限点属于管理数据。列表用于定位对象，详情用于检查继承、绑定用户、具体权限；不要把数十个权限卡片当成列表行。
- 审计过滤至少按时间范围、操作者、操作类型；列表显示人类可读动作，原始事件详情仍可追溯。
- 运行诊断先显示状态和异常，再折叠低频环境字段。健康状态必须来源于现有真实探针。

## 5. 实施任务包

所有任务只改 UI 和可验证的展示逻辑；保持 API 调用、权限条件、审核规则、流程定义、版本数据、资源密钥边界和执行副作用不变。开工前重新检查 git status，并保留本地既有修改。若某页面和本地源码不一致，先确认接口/部署版本，再改对应入口，不以远端页面推断本地代码。

## 6. 验收标准

### 6.1 布局、字段和按钮

1. 在 1440×900、1280×800、681×900、390px 和 200% 缩放下，页面外壳无横向滚动；只有流程画布本身允许二维平移。表格如确实需要横向浏览，应在表格容器内滚动并明确提示。
2. 1280×800 普通列表按照基础方案验收：首条记录在顶部约 240px 内出现，并至少能完整看到 8 条普通行；200% 缩放优先保证阅读与操作，不以行数为目标。
3. 业务中心和流程中心达到本文默认列集；不再靠固定 1400px 最小宽度把主操作推离视口。所有移出默认列表的数据在详情/更多字段中可读取。
4. 每页最多一个主色主动作。普通表格行最多一个常驻业务动作，其余使用有名称的更多菜单；危险动作分组、明确说明对象与影响。
5. 详情/仓库未选中对象时主内容回收空栏；零告警与零待办均有紧凑空状态；空状态不出现不可用的批量动作。
6. 画布在同一视口内明确为主体；关闭节点库和 Inspector 时面板空间回到画布。节点库、工具条、Inspector 不重叠，焦点可进出并可用键盘关闭。
7. 同一对象的名称、代号和统计不在顶栏、侧栏、标题和卡片中重复；字段分层后所有原始业务数据仍可从详情到达。

### 6.2 真实状态、安全和功能回归

1. 试跑按钮、标题、确认文案、结果状态与实际 endpoint 完全一致；只有经后端证实的隔离运行才能称“沙箱”。未证实前不做真实运行验收。
2. 保留新增/导入、审核、发布/取消发布、发起、审批、资源校验、授权、归档和版本动作的原权限与业务语义；界面整理不得更改其服务端调用目标。
3. 状态映射使用明确的正向字典和未知值兜底；加载中、无值、错误和真实数字有不同展示，不把缺数据渲染成 0。
4. 数据源凭据、SecretRef、完整访问地址、用户个人数据和运行内容继续遵循原有脱敏范围；截图不包括凭证、PII 和真实审批意见。
5. 验收至少覆盖长中文名称、长说明、无关联资源、未选中详情、零待办/零告警、加载失败、无权限动作和 20 条以上列表；不得只用空白页面截图。
6. 保存、撤销/重做、画布选择/连线、键盘操作、审核和执行按基础方案既有矩阵验证；样式验收不能替代真实端到端行为证据。
7. 验收报告记录浏览器、CSS 视口、DPR、缩放、账号角色、页面范围、截图路径、命令与退出码、未验证项。静态检查通过时不得写成线上验收通过。

## 7. 可直接交给 AI 开发者的实施指令

> 按《整体界面、信息架构与交互动效重构实施方案 v3.1》及本追加文档实施。开始先检查工作区差异和当前部署/本地页面结构，只修改授权任务文件，保留用户已有更改。先完成 UIR-00 页面基线，再依赖顺序实施 UIR-01 至 UIR-07。第一优先级是表格字段减负、项目上下文去重、画布空间回收、空详情区消除、按钮按状态分级；视觉 Token 与动效安排在结构之后。
>
> 业务中心默认显示业务名称/代号、流程数、工作域状态、创建时间和操作；流程中心默认显示名称/代号、类型、审核、发布、更新时间和状态驱动操作。详情页的字段和已有操作仍可达。流程设计器收拢节点工具为一个可搜索节点库，复用子流程移入库内，空选择时不占 Inspector 空间；只读视图隐藏添加节点工具。仓库默认目录与列表，选中后才开详情，完整画布须在可读尺寸下只读展示。
>
> 在更改试跑文案前，检查部署版本对应的服务端处理路径，确认隔离、队列、数据写出和外部调用语义。WorkflowTestRunModal 当前本地实现会先等待 onSaveDraft，再按类型调用 workflow.run 或 data.run；不得在未证实隔离前继续宣传“沙箱/纯仿真”，也不得为了验收对线上真实数据触发运行。
>
> 保持现有流程定义、数据来源、权限、审批、SecretRef、保存时机、运行 mutation、路由、键盘快捷键和撤销历史不变。不得伪造 API/统计值、删除字段、添加没有后端支持的按钮或从线上导入真实个人信息。逐批验证 1440×900、1280×800、窄视口、200% 缩放和不同数据量；最后交付逐项前后证据、实际测试结果、剩余缺口和回滚范围。

## 8. 未解决事项

- 远端页面和本地当前工作区是否为同一版本尚未核实；开始代码实施时须比对部署修订或询问部署负责人提供版本证据。
- 试跑是否真实隔离需要服务端路径或测试环境证据；在确认前本方案要求修正误导性承诺，不触发运行。
- 列表分页是否有后端支持需要核对查询接口；若无分页能力，按 UI 与接口契约一并实现，不做隐藏行的假分页。
- 资源、端点、账号和权限的编辑/确认弹窗仅检查了主要列表，没有执行提交；实施验收需在专用测试数据和明确权限下补充。
- 浏览器窄视口可能来自嵌入式浏览器窗口，不等于用户设备的实际响应式断点；需使用浏览器 CSS viewport / device scale 明确记录后再判定断点。
