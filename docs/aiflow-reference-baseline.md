## 原始控制/状态流程设计器契约

### 节点工具栏

`design_process.html` 明确提供以下节点入口，顺序和可用状态均应保留。SQL 节点及业务/物理资源在该版本中呈禁用态；还原界面必须显示禁用语义，而不能静默移除。

| 原始节点标识 | 原始展示名称 | 原始可见状态 | 现有安全执行映射 |
|---|---|---|---|
| `start-node` | 开始 | 可拖入 | `start` |
| `end-node` | 结束 | 可拖入 | `end` |
| `basic-node` | 状态节点 | 可拖入 | `state` |
| `operate-node` | 操作节点 | 可拖入 | `operate` |
| `route-node` | 路由节点 | 可拖入 | `router` |
| `subprocess-node` | 子流程 | 可拖入 | `subflow` |
| `rest-node` | REST 节点 | 可拖入 | `rest` / 安全 HTTP 分派 |
| `sql-node` | SQL 节点 | 禁用 | `sql` / 数据流只读 SQL 语义 |
| 业务资源 | 业务资源 | 禁用 | 资源引用入口 |
| 物理资源 | 物理资源 | 禁用 | 资源引用入口 |

### 画布与属性面板

原始界面要求保留以下操作和状态，而不仅是绘制节点外观：

| 类别 | 必须保留的可见细节 | 当前还原策略 |
|---|---|---|
| 画布主操作 | 保存画布、整理画布、保存为图片、全屏展示、取消高亮。 | 将每项转为可触发的设计器工具，图片导出需要生成真实画布快照。 |
| 配置进度 | 未完全配置（红）、配置中（蓝）、已配置（绿）图例。 | 由节点契约校验结果派生，避免仅通过节点类型猜测。 |
| 画布帮助 | 画布移动、画布缩放、节点多选、节点框选。 | 保留为可见帮助与键鼠可达提示。 |
| 检查器 | 空状态文案、配置面板锁定、最大化、还原、最小化。 | 以有状态面板实现；切换不得丢失当前未保存表单内容。 |
| 节点配置 | 选择画布元件后显示属性，未选择时显示“暂无配置信息”。 | 所有属性通过统一定义契约保存到 workflow definition。 |

## 原始流程设计中心状态与操作契约

`processDesignCenter.js` 证实，流程列表必须呈现如下列和状态，而不是只显示流程名称。

| 信息或操作 | 原始规则 |
|---|---|
| 流程类型 | `1` 为状态流程，`2` 为控制流程，`3` 为数据流程，并展示对应状态/控制/数据图标。 |
| 审核状态 | `agree` 使用绿色状态点，`reject` 使用红色状态点，其余使用灰色状态点；可以查看审批记录。 |
| 发布状态 | `published` 显示“已发布”蓝色描边标签；否则显示“未发布”灰色描边标签。 |
| 锁定状态 | 被系统流程引用的流程显示锁图标，并禁用不可删除/取消发布的操作。 |
| 已发布且审核通过 | 提供详情、发起流程或启动、取消发布、上传仓库（非数据流）和删除。 |
| 未发布且审核拒绝 | 提供详情、重置审核状态（创建者）、上传仓库（非数据流）和删除。 |
| 未发布且审核通过 | 提供详情、发布（创建者）、上传仓库（非数据流）和删除。 |
| 未发布且审核初始 | 提供详情、设计和删除。 |

## 原始数据流画布契约

数据流页面独立于控制/状态流程画布。其资源树、函数树、数据源选择器、加载状态、调度入口和运行状态提示都属于原始页面细节，不得以单一流程设计器替代。

| 区域 | 原始项 |
|---|---|
| 左侧资源栏 | 数据源选择；资源名称搜索及资源树；函数名称搜索及函数树。 |
| 数据流节点栏 | 交集、差集、并集、SQL、TSML（禁用）、中间表，以及动态插件区域。 |
| 顶部动作 | 一键展开、任务详情、调度配置、测试执行（隐藏态）、保存画布、动态流程操作区。 |
| 右侧画布动作 | 保存为图片、整理画布、运行（隐藏态）。 |
| 运行反馈 | SQL 运行、应用、画布保存、资源探查、配置面板加载，以及成功/失败/运行中状态浮层。 |

## 节点字段恢复方法

原始静态页面证实了节点类型和配置面板的存在，但缺失的 `bundle.js` 不足以证明每个内部字段名。为避免凭空添加或遗漏字段，下一阶段采用以下受约束方法：

1. 把当前可执行节点的配置字段、默认值、帮助文案和校验集中到单一 TypeScript 契约。
2. 对开始、结束、状态、操作、路由、REST、表单、SQL、转换、条件、LLM、子流程及数据流节点逐项建立“原始可见来源—持久化 JSON—执行器读取字段—校验规则”矩阵。
3. 任何未在原始页面或既有安全执行链路中出现的字段，必须标记为扩展字段，且不得替代原始可见字段。
4. REST 节点继续沿用服务端 SSRF 拦截；SQL 节点继续沿用只读校验；人工操作继续沿用持久化待办与服务端续跑，不能为了还原 UI 降级安全边界。
