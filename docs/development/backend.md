# 后端开发约束

## 从请求到落库

[HTTP 入口](../../server/_core/index.ts)装配 Express、中间件、tRPC、健康检查和 Worker。[业务路由](../../server/routers.ts)定义 Zod 输入、调用身份与领域服务。新增过程应明确输入、权限范围、幂等语义、返回结构和可见的错误。普通查询只返回当前页面所需字段，分页游标包括稳定的排序及并列时的 ID。

| 场景 | 实现要求 | 已有实现 |
| --- | --- | --- |
| 业务与流程变更 | 校验对象归属、有效角色、资源状态和读到的版本。发生竞争时在持锁事务内复核。 | [项目生命周期](../../server/project-lifecycle.ts)、[流程版本](../../server/workflow-revision.ts) |
| 创建、导入、审核 | 接口若支持重放，以作用域、请求标识和规范化内容判定同一次命令。写入对象、关联、请求结果与审计需遵循现有命令的原子边界。 | [流程创建请求](../../server/workflow-creation-request.ts)、[仓库导入](../../server/warehouse-import.ts) |
| 角色与组织 | 重新确认操作人、目标账号、角色配置及有效期。跨部门及主部门变更在同一事务维护关系和审计。 | [权限锁](../../server/iam-locked-permissions.ts)、[组织写服务](../../server/organization-write-service.ts) |
| 运行准入 | 依据当前流程类型、授权、审核、发布或测试模式检查。实例固定输入和执行计划。异步端点返回实例 ID，供查询、控制和对账。 | [运行预检](../../server/workflow-run-readiness.ts)、[数据流服务](../../server/p2-service.ts) |
| 办理与后台恢复 | 认领、表决、移交等动作复核当前任务资格和版本。作业按租约认领，完成、错误及重试写回对应作业，重复恢复须保持业务效果唯一。 | [任务服务](../../server/p1-service.ts)、[参与人运行时](../../server/participant-state-runtime.ts)、[Worker](../../server/workflow-worker.ts) |

## 执行合同

1. 在状态与控制流程中核对 [编译器](../../server/workflow-compiler.ts)、[执行器](../../server/workflow-engine.ts)和运行详情。新配置在编译与执行两侧表达同一语义。发布后的修改只影响按新版本创建的运行。
2. 在数据流中核对 [数据源能力](../../shared/data-source-capabilities.ts)、[资源预检](../../server/dataflow-resource-readiness.ts)、行转换与节点运行记录。质量失败要保留上游和失败节点事实，后继节点不会执行。
3. 手动运行、测试运行和定时运行各自携带准入身份及权限。取消后保留已完成节点，调度按 UTC 时间桶去重，启停与修改使用读取的 revision。Windows 主机时区不改变表达式解释方式。
4. 服务端的 `run.status`、`job.status`、待办状态和一次外部调用的结果具有不同含义。查询、指标和测试应分别观察其事务边界。详细回归示例见[测试约定](testing.md)。

## 人工办理的事务边界

从工作台调用 `task.execute` 直接办理待领取任务时，隐式领取、表决、人员卡片、状态转换、续跑作业及审计共用一次数据库事务。先锁实例，再锁任务，复核处理人、任务版本、个人可执行操作和顺序会签前序。成功时依次写入一条领取审计和一条办理审计，提交后才唤醒 Worker。表单、路由、权限、并发或审计写入失败时，任务仍为待领取，领取人、领取时间、版本及业务记录与请求前一致。[办理服务](../../server/p1-service.ts) · [续跑事务](../../server/workflow-engine.ts)

单独调用 `task.claim` 后，已提交的领取属于独立业务动作。后续 `task.execute` 或 `task.complete` 办理失败时，原领取人和原领取审计保留，处理人可修正输入重试。参与人任务已经成功后，同一办理人以相同规范化内容重放可取回原回执，提交不同内容会收到冲突。回归时分别从待领取、已领取开始，核对待办、人员卡片、审计、续跑记录和重放结果。[参与人数据库用例](../../server/participant-state.integration.test.ts)

## 外部依赖与错误

[服务端点](../../server/service-endpoint-service.ts)绑定项目、环境与受管凭据引用。使用现有连接策略、超时、响应大小限制和脱敏逻辑。记录请求标识、目标服务标识、状态及耗时，日志里省略密码、密钥、Cookie 和业务正文。供应商模型验证记录配置模型、返回模型、使用量与业务输出断言。外部服务失败时返回可定位的业务错误。

对可能已被第三方接收的写操作，先定义请求标识、查询结果方式和可安全重试的条件。数据库事务中避免等待外部服务。跨事务副作用可复用已有持久作业或 Outbox。重放时记录同一次业务动作的处理结果。

助手新增工具时定义角色、项目/流程范围、参数白名单、是否只读、准备提案和确认提交阶段。服务端用当前登录身份及原业务入口复核权限。管理试聊只模拟确认。回合以 `sessionId + revision + requestId` 核对，提案以独立操作回执核对。对话中生成的内容不能作为落库证明。[工作台工具](../../server/assistant-workspace.ts) · [助手后续设计](assistant-review.md)
