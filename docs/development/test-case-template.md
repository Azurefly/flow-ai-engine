# 用例卡与对照样例

复制以下表格即可从需求生成可执行的用例。验收人员在执行后填写结果及证据。新增自动化时，选能捕获该回归的最小层级，并为跨层承诺保留一条经过正常入口的链路。

| 字段 | 要填写的内容 |
| --- | --- |
| 用例与需求 | 稳定 ID、需求/评审编号、业务影响、优先级 |
| 环境 | 源码提交或镜像、数据库、浏览器、视口、实际连接的服务 |
| 前置与范围 | 操作人角色、项目和流程版本、授权状态、夹具标识与初始条数 |
| 输入 | 可复制的合成值、精确边界、操作标识、是否沿用上次请求 |
| 步骤 | 用户或调用者的正常入口。每步的可见结果及下一步启动条件 |
| 判定 | UI 内容或焦点、接口结果、对应持久化记录、数量、下游副作用。异步截止条件 |
| 收尾 | 应清理/归档的本次对象，必须保留的审计事实，复跑如何生成新夹具 |
| 执行记录 | 执行者、时间、实际结果、证据文件、失败归属及复验版本 |

## 可直接转成自动化的样例

| 用例 | 前置、输入和动作 | 验收断言与收尾 |
| --- | --- | --- |
| CSV-01 / F03，多行中文说明 | 可创建业务的账号，唯一业务代号。UTF-8 BOM 文件，表头 `code,name,description`，说明字段用双引号包住，字段内有真实 CRLF，重新打开业务列表 | 恰好创建 1 条记录，说明保留两行。替换为缺失闭引号的输入应得到逻辑行、列和原因，创建数为 0。归档本次项目。 |
| CSV-02 / F04，纠正半成功批次 | A 行合法，B 名称 300 字。预检后缩短 B 名称，提交、刷新并再次提交原请求 | 依整改合同，首次预检时写入为 0。执行期中断则列明每行状态。纠正后 A 与 B 各 1 条，重放同一批次时 A 的审计与项目数量均不增加。 |
| DATA-01 / F05，回执丢失 | 有运行权的用户、已发布无外部写出的数据流。客户端提交后丢弃第一次回执，以同一请求标识重试，同时从另一连接查询 | 两个回执指向同一 `runId`，一个入队作业。改变请求内容沿用旧标识时收到冲突。明确再次发起使用新标识得到第二个实例。收集两次请求与只读计数后归档夹具。 |
| SIGN-01 / F06，或签后后台收尾 | 两个具备资格的用户、或签流程、两个独立会话。首人同意，另一人刷新并尝试办理，随后等待该实例的恢复作业终态 | 仅一人办理生效，旧待办失效，业务出口执行一次。分别断言流程 success 与该作业 completed，截止时输出该实例作业与租约状态。 |
| UI-01 / U01，弹窗返回焦点 | 桌面键盘，普通/减少动效各执行一次。从“新增业务”按钮 Enter 打开空表单，依次测 Esc 和“取消” | 打开后焦点在弹窗内。关闭并卸载后焦点位于原按钮，Tab 从原位置继续。触发按钮若已被移除，定位到该区域稳定的可聚焦标题或主动作。 |
| CONN-01 / G01，分页中断恢复 | 项目自己的合成 API，有两页和恒定记录 ID，第二页首次响应失败。断开并恢复连接，读取产物与血缘 | 首次错误指向源节点与页次。重试后每条源记录只出现一次，失败尝试与恢复尝试均有记录。回收测试端点和产物。 |
| AI-01，确认与回执重放 | 客户从有权项目请求创建唯一名称的目录。直接查仓库、确认、再次用同一 requestId 和版本确认，然后从历史重开。另用管理试聊重复操作 | 确认前 0 个，确认后 1 个，重放仍 1 个且会话修订相同，试聊无业务写入。撤权后原提案不能执行。归档本次项目。 |
| AI-02 / F09，历史分页 | 专用账号分批创建会话，包含同一时刻更新的项目 A/B 记录。按项目检索，翻页途中撤销 B 的权限，在旧会话回复 | 每页最多约定数，无重叠遗漏，撤权生效，旧客户端查询仍可工作。一条新回复仅追加一次，切换会话不会误确认另一个项目的操作。 |

上表中的整改合同随开发验收生效。“现状已实现”和“设计待交付”由[评审摘要](review-baseline.md)及实际测试结果判定。[完整设计](remediation-design.md)
