# UI 与动效评审

审计时，业务中心用键盘关闭弹窗后焦点落到页面主体，导入失败提示也会跟进编辑画布。整改后，关闭弹窗能回到原按钮，错误行留在原批次。画布在 50% 和 100% 起始缩放、两种动效偏好下均实测了节点和连接点的命中范围。下表保留开源研究、原始测量和选型理由。手机触控、软键盘和真实读屏的交付条件见 A43、A50。[整改与实测](optimization/IMPLEMENTATION.md) · [验收场景](optimization/ACCEPTANCE.md)

## 从四个开源项目读取的设计依据

2026-11-19 先阅读以下 GitHub 源码，再用本项目的真实页面验证。链接固定到本次读取的提交。以下是实现机制与适用判断。

| 开源项目 | 读到的具体做法 | 在本项目的取舍 |
| --- | --- | --- |
| Motion | `AnimatePresence` 按稳定子元素 key 跟踪出现和离开，等待退出参与者完成后再移除元素。 | 适合需要短暂保留“刚完成”行的任务清单。编辑表单若随数据刷新反复卸载，会丢输入和焦点。保留已有 DOM 与草稿。 [AnimatePresence 源码](https://github.com/motiondivision/motion/blob/3a1ce87441f1055285ebf0099f842c3ca702d9e3/packages/framer-motion/src/components/AnimatePresence/index.tsx) |
| FormKit AutoAnimate | 观察父元素的直接子项变动和元素尺寸，计算新增、移除、位置变化。默认遵从系统减少动效偏好。 | 只在用户主动插入、删除或重排少数条目时借鉴。工作台轮询、服务端翻页和长列表采用稳定行高与内容更新，避免整页漂移。 [AutoAnimate 源码](https://github.com/formkit/auto-animate/blob/29ee7a939f019b9f16e88166b1a880f9fe9456bc/src/index.ts) |
| Radix Primitives | Dialog 关闭时通过 `onCloseAutoFocus` 和 `triggerRef` 把键盘焦点送回触发控件。受控弹窗需知道真实触发者。 | 本项目已有 Radix。为可复用创建弹窗传触发按钮引用或使用 `DialogTrigger`，在实际卸载时恢复。嵌套确认先回到上层表单。原行被移除时用列表稳定标题兜底。 [Dialog 源码](https://github.com/radix-ui/primitives/blob/1e3759dff0504268072fb94656b118fa6e531408/packages/react/dialog/src/dialog.tsx) |
| xyflow | `setViewport`、`setCenter`、`fitBounds` 共用视口控制层，调用者可传时长等选项。 | 画布已有同类入口，可在一处决定可用区域、偏好和动画时长。用户明确定位时移动，拖动或连续定位以最近一次操作为准。 [视口控制源码](https://github.com/xyflow/xyflow/blob/4988e2bf80c0c69b435d82daa440ab3abdecfb39/packages/react/src/hooks/useViewportHelper.ts) |

## 本站实测

发布镜像的本机隔离副本使用无头 Edge，桌面视口 1440×900，移动视口 390×844。普通和减少动效各开一份浏览器上下文。系统偏好由 `matchMedia` 回读，动画时长来自实际元素的计算样式，画布通过逐帧读取视口矩阵观察。矩阵数量只描述本次操作，不能当作设备帧率。

| 操作 | 普通模式 | 减少动效 | 结论 |
| --- | --- | --- | --- |
| 新增业务，检查打开状态 | 进场计算时长 200 ms，焦点进入弹窗 | 计算时长 0.01 ms，焦点进入弹窗 | 减少动效已生效 |
| 空表单按 Esc，等待关闭完成 | 焦点落到 `BODY` | 焦点落到 `BODY` | 两种模式都丢失触发按钮 |
| 画布从起点定位到终点 | 两次验收各采到 10、19 个不同矩阵，最终均选中 end | 两次均只有首尾 2 个矩阵，最终选中 end | 目前这条定位路径符合减少动态效果预期 |
| 桌面拖动并保存 | 最新副本命中真实节点标题后拖动，草稿 v2→v3。刷新读回同一坐标。通过配置面板再改名，v3→v4，重开名称一致 | 本项只测普通模式 | 视口定位、节点位置与持久化应各有断言 |
| 手机打开业务列表 | 页面宽度与滚动宽度均为 390 px。表内“流程数”纵向逐字换行，行尾动作在右侧 | 本项只测布局 | 整页无横向溢出仍无法说明列表易读、易操作 |

发布构建已有 `useMotionPreference`、`useContextReveal` 与主题过渡。源码里的上下文揭示时长为 180 ms，减少动效时跳过，已有动画可以取消。最终发布源码 `8964f07` 为 511.25 / 512 KiB gzip，余额约 0.75 KiB。动效补丁应提供同口径的构建差额。[偏好钩子](../../client/src/hooks/useMotionPreference.ts) · [上下文动画](../../client/src/hooks/useContextReveal.ts) · [预算脚本](../../scripts/check-bundle-budget.mjs)

## 修改意见与验收

| 编号与优先级 | 修改落点和行为 | 怎么判定完成 |
| --- | --- | --- |
| U01 / P1　弹窗关闭焦点 | 优先处理“新增业务”。由 `CreationDialog` 接收真实触发者，为 Esc、取消、提交成功、打开二次确认制定回焦目标。提交中关闭规则保持一致，用户能用键盘读到无效字段。 [创建弹窗](../../client/src/components/CreationDialog.tsx) | 普通、减少动效分别用 Enter 打开，用 Esc / 取消 / 成功提交关闭。断言 `activeElement`，再按 Tab 检查下一站。适配触发者被移除和嵌套确认。 |
| U02 / P1　导入错误留在业务上下文 | 将批次结果放进导入面板，提供“已创建 / 待纠正 / 未处理”、行列、中文原因和下载错误行。全局短提示只指向该批次。实测从导入页切到编辑器，早先的导入提示仍出现在画布截图上。 [业务中心](../../client/src/components/ProjectWorkspace.tsx) | 纠正一行后续传成功。跳页时画布操作区没有无关导入提示。返回业务页还能找到失败行。错误用持久文字和关联字段呈现。 |
| U03 / P2　移动业务列表 | 390px 首屏优先显示业务名称、代号、状态和进入工作区入口。将工作域、流程数和其他动作放入每行展开详情或单菜单。桌面保留可比较的多列表格。 [业务列表](../../client/src/components/ProjectWorkspace.tsx) | 在 360、390、768px 使用长中文名和长代号，验证名称与状态可读，流程数不逐字直排，进入业务无需横移。菜单用键盘和触屏均可操作。 |
| U04 / P2　编辑器视口与面板联动 | 次要选中态和工具栏只做短淡入。计算定位范围时扣除可见配置面板、滚动条和边距。保留拖动起点、用户缩放和全屏返回位置。桌面截图中末端节点靠近配置区边界，作为布局验收样本。 [流程画布](../../client/src/components/WorkflowCanvas.tsx) | 检查左中右三个节点、窄面板/展开/全屏，以及 50% 和 100% 缩放。选择后节点标题与连接点可见，拖动中视口不反向抢位。减少动效直接到终点，保存后节点坐标一致。 |
| U05 / P2　待办和运行状态 | 明确区分主导航、所在页、列表选择与状态标签。相邻“最近任务”区域按待办动作或历史含义命名。用户主动办理后仅强调发生变化的一行，后台轮询保留滚动位置、焦点和选择。 [工作台](../../client/src/components/ProcessWorkbench.tsx) | 同一列表连续三次轮询没有新增状态时保持位置。办理成功，待办列表移除对应任务并提供可查结果。慢返回时持续显示“提交中”，键盘焦点有明确去向。 |
| U06 / P2　助手历史和确认 | 当前悬浮面板与试聊在 390px 可操作，历史入口使用普通下拉框。改成按项目筛选的分页列表，明确显示当前提案的目标与确认后状态。长回复保留人工滚动位置。 [助手聊天](../../client/src/components/AssistantChat.tsx) | 有 60 条历史时能用键盘找到旧项目会话。进入提案、取消和确认后焦点有去向，减少动效时无自动平滑滚动。切换项目始终能分辨当前待确认对象。 |

建议首轮优先沿用 CSS、现有小钩子和 Radix。可试验的时长为按压反馈 80–120 ms、普通浮层进入 140–180 ms、退出 100–140 ms。这些值由交互样机验收决定。区分用户操作、后台刷新、路由跳转三种触发。用颜色或位移呈现的状态变化同时提供文字或图标。对减少动效偏好，保留状态变化及焦点，关闭非必要位移。

## 开发交接
