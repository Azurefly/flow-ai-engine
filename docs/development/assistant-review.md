# AI 助手专项评审与设计

下文保留最初评审的基线。当前版本的长历史已分页，长回合进入持久作业。运维开关、进程中断恢复和真实供应商联测分别见[后台回合](optimization/G04-IMPLEMENTATION.md)及[实施回执](optimization/IMPLEMENTATION.md)。

## 从助手创建流程

在目标业务打开启用“创建流程草稿”的助手，说明流程类型、步骤和必要的办理人或数据资产。助手生成画布后，可先预览和修订，再点“确认执行”。保存成功后，从对话里的“打开流程草稿”进入实际设计器。创建沿用业务项目的权限、初始审核状态及幂等创建回执，发布和发起继续从流程工作区操作。

状态流程可定义业务状态和人工步骤。控制流程的并行分支使用与类型相符的汇聚节点。数据流程可绑定当前项目已有可读资产，筛选、选择字段、分组聚合并命名结果。同名资产需指定 ID，依赖固定读取的资源版本在预览中可见。运行引擎继续核对当前资源与权限。[工具与画布校验](../../server/assistant-tools.ts) · [草稿回执](../../server/workflow-creation-request.ts)

迁移 0051 为未经改动的系统“流程助手”启用创建草稿。管理员自定义的助手按发布配置提供工具。已有对话使用发起时选择的工具版本，升级后可新建对话。[默认配置迁移](../../drizzle/0051_assistant_workflow_creation_default.sql)

审计对象包含发布给客户的悬浮助手、`#/system/agents` 配置、草稿试聊、会话存储、业务查询与变更确认。线上真实模型成功完成项目统计和创建目录，回执重放没有第二次写入。优先补齐长历史检索与长回合运维。真实业务办理和多轮恢复应继续沿用已验证的确认与授权边界。

## 已验证的链路

| 入口与环境 | 实际结果 |
| --- | --- |
| 部署镜像 `8964f07`、真实外部模型 | 新建专用项目，助手回答的流程数与直接业务查询均为 0。模型提出“创建流程目录”，待确认时通过仓库仍读到 0 个。确认后 1 个，重放相同请求仍为 1 个，会话修订保持 3。重新打开历史有 8 条消息，原请求可核对。归档后活动业务 ID 集合恢复。 |
| 同一提交、Edge、真 MySQL、受控模型 | 管理员创建助手并保存，试聊模拟确认没有修改水印，客户入口确认后数据库水印改变。普通账号能定位本人的待办和已办，不能使用管理员水印工具。补充办理人后预览可恢复，确认的草稿能打开画布。390px 下管理、试聊、发送按钮可用。 |
| 同一浏览器验收中的恢复场景 | 首次 `start` 已提交后丢弃回执，刷新后原文仍在，重试只有一份会话和一个回合。双标签基于同一版本提交，落后请求被拒，原文可重发。历史读取中断后可原地重试。该次共调用回环模型 14 次。 |
| 同一提交专项用例 | 4 个单元文件 22 项通过，2 个真实 MySQL 文件 10 项通过。覆盖提案修改、草稿/发布版本、角色与工具撤回、相同请求回放、不同用户独立会话、写操作回执恢复、工作台统计与写入只发生一次。 |

模型在本轮真实环境只做了项目统计和创建目录这两项工作。会签、移交流程、跨权限历史和水印的助手回归采用真实业务代码和隔离数据库，模型输入由受控夹具决定。供应商自由措辞、长上下文理解率和目标用户并发容量仍需各自的样本及验收。

## F09 / P2　历史列表与长会话

提交 `8964f07` 的 `assistant.sessions` 返回当前可见会话的完整数组，UI 渲染为选择框。专用新账号经正常业务过程依次创建空会话，1、30、60 个时分别返回 1、30、60 项，序列化正文为 271、8,101、16,201 字节。列表没有游标。单个会话按修订加载所有回合。模型取最近 32 条消息作为交流上下文。前者涉及阅读成本与响应体，后者涉及较早要求的保真度。这组测量没有给出线上延迟结论。[会话服务](../../server/assistant-store.ts) · [回合执行](../../server/assistant-runtime.ts) · [历史选择器](../../client/src/components/AssistantChat.tsx)

**设计。** 增加兼容的 `assistant.sessionsPage`，参数为项目、助手、关键字、pageSize 与不透明游标，排序固定为更新时间和 ID。服务端在可见范围内分页，撤权导致的空记录继续向后取，游标绑定筛选条件。只有当前页需要返回摘要。前端支持键盘检索、项目标识、显示历史上下文、载入更多和焦点恢复。原 `sessions` 供旧客户端使用。

**长会话。** 增设按修订向前翻页的消息查询。打开会话只取近期窗口。提案与未完成业务记录按真实 ID 加载。对长期任务保存目标、已确认约束和关联业务 ID，旧摘要携带来源回合区间，可查看原文。需要归档会话时保留业务回执和关联审计的既定保留期限。

**验收。** 以同一用户多项目 200 条会话、同秒更新、翻页期间新增、撤权、历史项目归档及长对话修改提案为样本。核对页大小、可见记录、无重复或遗漏。旧账号及旧会话可查。明确性能基线后再设目标延迟。按用户组启用入口，旧查询可支撑前端回退。

## G04　长回合执行、状态和回执核对

目前 `mutateAssistantSession` 在持有会话行锁的事务里等待工具和模型返回，每个进程最多同时处理 6 个回合。工作台写工具在派发前登记回执。领域写入与回执登记存在中断窗口，遇到结果未知时停止重复提交。现有同请求去重和必要的权限检查已有集成覆盖。长期占用连接、单进程限额与多实例协调是架构风险，本轮没有据此推算可支持的在线人数。[会话事务](../../server/assistant-store.ts) · [工作台写回执](../../server/assistant-workspace.ts)

1. **短事务接单。** 建议持久化回合作业，键为会话、请求 ID、基准修订和内容哈希。事务内校验权限并登记 queued，快速返回作业 ID。Worker 领取租约，在事务外等待模型，分阶段记录 awaiting_model、awaiting_confirmation、已完成或失败。
2. **权限与次序。** 同会话按修订推进，持有租约的一方才可提交结果。发起时的权限用于解释记录，执行工具和最终写入仍按当前角色、项目和允许的工具重核。角色撤销、范围收缩、取消或旧租约返回时，避免对用户产生额外副作用。
3. **业务回执。** 新工具优先向原领域命令传递稳定操作标识，存储实际目标、业务结果编号、可查询状态。结果未知时只查询原命令。无法被原领域核对的操作向支持人员展示请求号、对象、事件时间和建议核对位置，并记录核实者及结论。
4. **用户反馈与观察。** 提供状态查询、取消尚未派发的回合，以及清楚的“等待确认 / 已提交待核对 / 已完成”。诊断记录首响应时间、各阶段耗时、失败原因和待核对积压，省略原始会话内容及凭据。
5. **验证与退回。** 受控模型延迟、断开、重复返回。进程重启、多副本竞争、授权撤销、业务已写但回执尚未补齐。核对后只出现一次真实变更。先给只读工具启用异步执行，验证后再启用写提案。旧同步请求仍可按已有 requestId 查结果。

开发时用[后端约束](backend.md)、[用例模板](test-case-template.md)和[动效交互 U06](ui-motion-review.md)共同验收。模型提示“已完成”需要与业务记录、会话回执及当前授权三者相符。
