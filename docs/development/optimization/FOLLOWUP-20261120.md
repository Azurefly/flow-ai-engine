## 电脑网页端与恢复演练

Windows 桌面 Edge 149 使用 1440×900 视口。键盘在业务列表展开并关闭两行详情，关闭后焦点回到原控件。两轮搜索只保留目标业务，进入后可通过浏览器返回。使用空缓存访问 404 页、登录与业务列表时，无画布资源请求。进入流程编辑器后浏览器下载画布资源，并渲染合成流程的起点。Windows 生产包的 JavaScript 总量为 1,688.75 KiB，gzip 合计 522.53 KiB，分别通过 1,694 KiB 和 525 KiB 的门槛。

助手在同一桌面浏览器完成中文组合输入。选词回车没有发送请求，Shift+Enter 保留换行，普通回车提交一次。断开连接时由另一真实 HTTP 会话发来回复，恢复连接后正在阅读的位置保持在 60 像素，主动跳转到末尾。经过真实应用、自建模型对端和 MySQL，键盘取消、确认与管理试聊分别写入 0、1、0 个目录。Chrome DevTools 协议驱动组合输入，浏览器无障碍树确认对话区的名称、`log` 角色与即时状态。

跨主机演练先在 Windows 的专用应用中创建并完成父子流程，再通过 SSH 把合成 SQL 备份送到远程主机。无网络的临时 MySQL 依次验证 62 张表、51 个迁移、四个会话索引、已归档项目、固定子流程版本、父子运行结果摘要和一条已办理待办。冷启动至回读一致耗时 11.42 秒。生产备份的异地存储目标仍待指定。

## 助手分页与容量

同一独立 MySQL 中创建含 1、30、60、120 和 1,200 条会话的样本，比较迁移前后的 `EXPLAIN ANALYZE` 和返回 ID 顺序。120 条样本、页面大小 7 时，旧查询扫描 120 条并排序，返回 33 条候选。新查询按索引读取 8 条。深分页也只读取当前页候选，覆盖同秒 ID 顺序。试聊、普通会话、全局、项目、指定助手及项目与助手组合均检查执行计划。

容量使用专用 MySQL、真实应用 Worker 和本机 HTTP 模型对端。每轮先建好独立会话，再同时入队。按作业表的创建、开始和完成时间计算延迟，以真实对话中的请求回执核对结束。

| 会话数 | 模型固定延迟 | 作业 P95 | 作业 P99 | 排队 P95 | 失败 |
| --- | --- | --- | --- | --- | --- |
| 6 | 250 ms | 1.542 s | 1.542 s | 1.221 s | 0 |
| 24 | 250 ms | 4.719 s | 4.734 s | 4.411 s | 0 |
| 24 | 1,200 ms | 16.020 s | 16.052 s | 14.761 s | 0 |

三个批次都观察到最多 2 个并行模型请求和 2 个有效租约，连接等待计数峰值为 0。A67 的业务目标并发、供应商延迟分布和可接受尾延迟仍待确认。生产验收沿用同一测量口径。
