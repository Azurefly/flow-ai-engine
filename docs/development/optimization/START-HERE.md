## 建议分工与依赖

| 工作顺序 | 负责角色 | 切分及合并要点 |
| --- | --- | --- |
| F01、F02 | 测试维护者、身份与部署负责人 | 源码整改与部署配置可分别推进。轮换、会话处置、正式证书与公网验收由拥有相应变更权限的人执行 |
| F06、F07 | Worker / QA | 可同产品整改并行。F06 作用于真实 MySQL 断言；F07 作用于 HTTP 验收夹具。保留失败的退出码。HTTP 仅指向明确的专用环境 |
| F03 → F04 → U02 | 业务导入前端、项目服务、交互 | 先确定解析结果与行标识，再共用预检/批次合同，最后接入持久结果面板。F03 和 U01 都涉及业务中心，按函数拆差异 |
| F05、F08 | 数据运行、模型节点 | F05 兼容三处调用方。F08 保留历史显示和使用量计算。和其他任务同时新建迁移时，按实际分支的顺序生成迁移并核对元数据 |
| U01、U03、U04、U05 | 交互与前端 | 按页面独立验收。改公用弹窗先抽查另外两个实际调用方。画布使用真实节点命中和可见几何范围断言 |
| F09 → U06 | 助手后端、交互 | 先确定可见项目/助手、稳定排序和翻页，再接历史面板、提案焦点和桌面键盘交互 |
| G01、G02、G03、G04 | 数据连接器、流程引擎、内部身份、助手运行时 | G01 用独立交换服务核对固定版本读取、写前预览和最终回执。G02 用真实人工任务验证父子关系。G03 对本系统的账号、部门和成员关系做差异预览、逐项应用与回退。G04 与 F09 保持详情和历史读取兼容。 |

## 可直接交给开发智能体的任务说明

> 在 Flow AI Engine 仓库接手 U06 的 A50。先读 Agent.md、开发索引和 A50 的 verification，核对测试版本。用获准的账号在桌面浏览器完成中文组合输入、客户取消和确认、管理试聊。记录键盘焦点、读屏状态、收到新消息时的阅读位置和业务对象回读。遇到缺陷时从 AssistantChat 和会话服务定位，在队列登记版本、操作步骤和修复证据。

派其他任务时替换编号、验收编号及相应入口。`queue.json` 中每张卡都有完整的实施和验收文本。接手 G 类任务可从模块交接文档中的正式入口、隔离样本、可重放的回执和回退步骤复测。

## 工作环境和回报格式

Windows 11 使用 PowerShell。在仓库根目录执行下列只读核对，再选用本任务所需的门槛。包管理器按 `package.json` 声明和仓库锁文件。真实 MySQL 门槛前应指向专用已迁移的测试库，套件会更新设置与作业队列。仓库开发约束中的 `docs/development/testing.md` 与 `database.md` 说明环境要求。

```powershell
git status --short --branch
git rev-parse HEAD
pnpm exec vitest run --config vitest.unit.config.ts server/project-import-preflight.test.ts
```

在已配置隔离库后，可由签署任务执行以下定向门槛。独立创建两个初始环境的要求适用于 F07 的自包含验收。实际运行的命令、退出码及精确范围写入回报。

```powershell
pnpm exec vitest run --config vitest.mysql.config.ts server/operate-signing.integration.test.ts server/workflow-worker.integration.test.ts
```

| 回报字段 | 要写到什么程度 |
| --- | --- |
| 任务和版本 | 任务编号、原基线、修复提交/工作树指纹、隔离环境及迁移版本，注明供应商是真实或受控 |
| 原问题与变更 | 实际业务入口、基线复现、改动文件、对外合同、兼容的历史数据与回退开关或版本 |
| 验收与证据 | 按 A 编号记录通过、失败或待验，给出命令/角色/样本、预期与实际、回读计数与脱敏证据。截图不能代替写入回读 |
| 发布决定 | 已解决的具体风险、仍需人类签收或外部测试的项、是否影响发布。涉及表或作业时说明部署顺序、处理中请求接管和回退后的可读性 |
