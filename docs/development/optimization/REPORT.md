### 3.2 业务中心、项目授权、导入与外部同步

管理员从业务中心新增项目并按代号检索，再进入工作区、权限配置、服务端点和资源配置。真库覆盖成员可见性、按部门授权、项目创建流程字段和原始流程保护。项目创建与查询的普通路径成立。浏览器六项 CSV 数据观察包括失败重试的前后回读，给出了两类可直接改变业务数据的缺陷。E02–E05。

| 合成输入及操作 | 期望终态 | 实际终态 |
| --- | --- | --- |
| UTF-8 BOM，说明含逗号与一个转义双引号 | 建一条且说明原样保存 | 通过。服务回读 `含逗号,与引号"甲"` |
| 一个引号字段中含真正的换行 | 同一业务记录保留两行说明 | 浏览器报“每条业务记录都需要业务代号和业务名称。”，目标业务不存在 |
| 说明只有开引号 | 指出记录、字段和缺失闭引号，业务写入为零 | 目标业务存在，说明保存为“不完整内容”，原错误被掩盖 |
| 首行 A 合法；次行 B 名称 300 字符；限制 160 | 静态错误在写前发现，用户能更正后重新提交 | A 已经创建，B 缺失。反馈含原始英文校验 JSON。修正 B 后重传，A 的已存在校验拦截整批，B 仍缺失 |

F03 要求对整个字符流识别逻辑记录。F04 要求全批静态预检、逐行执行回执、刷新后的恢复能力。单行创建保留当前权限、审计和归档占码规则。BDP 同步按钮固定禁用，界面中看不到预览、映射或同步结果。G03 在取得上游合同前只承诺差异与应用模型，避免使用者误判可交付范围。

### 3.3 设计器、流程治理、模板与流程仓库

设计者创建流程、打开详情和画布。在最终副本中首次保存使草稿 v1→v2，第二次先命中可拖动标题再拖拽，v2→v3，刷新后读回保存坐标。配置面板改名后 v3→v4，退出重开仍为新名称。初次坐标尝试受命中位置影响，后续受控测量以实际元素和持久化值验收。E03、E16。

仓库用三个流程类型执行导出、导入预检、导入、请求重放、正式/测试运行、归档与恢复。预检没有写草稿，整组产生 7 个运行 ID。浏览器单独检查仓库标题并进入归档面板。MySQL 另验草稿快照、发布、历史、权限与所有者。通过条件是旧定义可重读、导入请求有既定结果、归档及权限仍约束资源。E02、E05、E06。一次发布的特定标签合同已变更，F07 记录旧脚本如何在进入运行前失败。

### 3.4 状态流、控制流、任务和作业恢复

| 业务合同 | 测到的状态与配对证据 | 整改时要保护的合同 |
| --- | --- | --- |
| 项目发布后发起状态流程 | 正式实例到达 `RECEIVED`，有 3 次节点运行。参与人真库有 8 个用例，覆盖人、操作、撤回、旧待办失效及事务竞争。E02、E05 | 同一参与人的重新提交有新的执行身份，旧任务继续不可办。并发时核对持久事实与可见状态 |
| 设计者组合条件、广播和循环 | 最终镜像控制与状态循环分别访问 3 次；定时等待 3 次；人工循环产生不同任务；并行分支分别访问 3、2 次并汇合 2 次。内联子流程返回 2 次；达到声明上限后实例失败。E06 | 每次访问保存独立事实。维护循环计数、匹配的汇聚及明确的超限终态 |
| 并行人工或消息使父实例推进 | 两组独立 HTTP 套件通过，办理身份、消息去重与单次汇聚可观察。早期独立夹具验证旧标签、优先、广播、兜底四种路由。最终原标签脚本仍红。E06–E08 | 广播的两个命中分支都执行，优先模式只取目标分支。不能因旧脚本失败放松编译或发布校验 |
| 办理人以签署、移交或委托完成工作 | 真实页面办理后任务 completed、实例 success；HTTP 涵盖或签、100/66/1 阈值、并发与顺序、移交/委托、加减签。已有场景结束节点只执行一次。E02、E07、E16 | 旧办理人再次提交应被拒。实例成功和恢复作业完成分处两个提交点；F06 要分别等待并断言 |

同步子流程已执行内联及循环，嵌套定义在实际创建时被拒。需要“子流程独立等待人工或消息、父流程可恢复”时，G02 设计父子实例关系、唯一续跑事件和权限。参照状态流历史的用户须分别获得两端读取权限。

并行消息专项日志对“重启后恢复、旧等待快照、暂停恢复、撤销发布生命周期”的可选标志均未置真。这些组合须在改动相应机制时另验。仓库套件自身的暂停/继续/终止、权限一致、缺资源拒绝和 3 次显式幂等重放均有断言。E06 逐项保留了原布尔值。

### 3.5 数据资源、转换、运行与运维

资源中心在浏览器访问数据源、探查、函数、标签、项目插件和数据流六个页签。MySQL 集成覆盖真实只读数据源、资产约束、登记与项目授权、运行产物与血缘。API 数据源可探测，文件数据源可登记，二者用于 source 节点的实际读取均在预检被拒。现有数据流 sink 接受 `audit_only`。工作流另有可执行 HTTP 节点。接入外部数据的报价、排期和 UI 选项应按具体方向分别表达。E02、E03、E11。

| 用户动作 | 观察与验收判断 |
| --- | --- |
| 关联数据、应用函数与去重 | HTTP 关联/函数、筛重两组通过。筛重样本 6→4、汇总 100；另一组 3 条、汇总 40。应同时断言行数、键与数值，便于发现只保留数量而误删具体行的回归。E11 |
| 检查质量阈值 | 同样样本，最大空值率 0.25 时失败且不执行终点，0.50 时成功。非法 1.1 在创建即被拒，原脚本期待较晚才失败。该脚本退出后的其他异常输入尚需拆用例。E08、E11 |
| 人工运行并核对结果 | 对无外部写出的同一已发布流程，客户端在服务已接单后主动弃用首份成功响应，再次发相同输入。出现两个不同的 `manual` 运行 ID，各自成功。F05。这里模拟了用户不知道结果的条件，未注入实际网络故障。E09 |
| 启动、暂停和取消 | 排队任务取消成功。分钟 cron 真实触发并成功；用过时修订暂停返回 409，随后正确修订完成暂停与删除，列表无该条目。补充的慢查询样本取消返回 30 ms，受控锁保持时 150 ms 后 Worker 仍在等待，释放后收尾；源节点 cancelled，后继未运行。E09 |
| 查询监控、运行指标和告警 | 监控页可进入，实例和节点历史可读。对自建样本，空样本、已完成运行耗时、待办后终止进入不同分母。终止样本最终总数 1、计时样本 0、均值 null。固定的外部流程 ID 触发无权限拒绝，F07。告警权限有真库覆盖；真实接收方送达需联测。E02、E10 |

容量与恢复结论限于已检查的特定状态。即使 UI 已返回“已取消”，底层连接何时释放仍需在目标驱动和工作负载下观测。尚无生产并发度、尾延迟、跨节点故障切换或恢复时间实测值。

**助手的执行边界。** `listAssistantSessions` 先按 owner/trial 等查询候选，再按当前项目、流程及发布范围逐项过滤。分页时直接对原 SQL 加 `LIMIT` 会导致空页假结束或跳过可见项。`mutateAssistantSession` 在取行锁后等待回合处理，进程内上限 6 个活跃回合。工作台写工具先预约回执，再调用业务命令并回填结果。业务已提交而进程中断时存在“结果待核对”的窗口，现有逻辑遇到未知状态会阻止再次派发。G04 建议有后台作业、租约和目标业务回执后再扩并发。以上是由源码推导的压力与恢复风险，已有真实确认重放成功这一结论仍成立。
