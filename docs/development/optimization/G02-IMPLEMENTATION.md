# G02 持久父子流程交接

控制流程和普通状态流程的「子流程」节点提供「持久调用·支持人工与消息」。调用者选择目标发布版本、入参和返回字段，父实例保持等待，子实例独立创建待办、领取作业和保存上下文。审批人员可以在工作台办理子任务。父、子实例详情提供有权读取的对端链接。旧私有子流程继续按原同步快照运行。

## 设计和实际入口

| 事项 | 行为及维护位置 |
| --- | --- |
| 定义、选择与预检 | [节点契约](../../../shared/workflow-node-contract.ts)、[选取表单](../../../client/src/components/DurableSubflowPicker.tsx)和[绑定服务](../../../server/durable-subflow-binding.ts)共用执行模式。选择对象后保存工作流 ID、不可变发布版本和 SHA-256 执行摘要。运行前校验入口重新核对目标可见、可运行、已发布且未归档。 |
| 嵌套与并发 | 首期支持一层调用。自身调用、含另一子流程的目标版本、参与人状态卡模式会给出父调用节点的定位诊断。每份定义最多八个持久调用节点，每个父实例最多八个同时进行的子调用。 |
| 启动和等待 | [执行器](../../../server/workflow-engine.ts)在锁定运行租约之后，用同一个数据库事务保存等待订阅、调用节点等待态、子实例、子作业和关系。串行父调用还在同一事务结清父作业并停在等待态。并行父流程交由各分支的检查点继续推进，汇聚时仍需收到子结果。 |
| 版本与权限 | 发布或恢复父流程时重新核对绑定。运行时按发起人的当前父子流程权限取同一版本的执行计划，校验摘要，再解析子流程中的参与人。子实例保留自己的触发人、权限记录、表单和输入。父节点的传入值须解析为对象。 |
| 终态与恢复 | [关系处理](../../../server/durable-subflow-runtime.ts)按父实例、节点、分支/循环执行键、尝试序号唯一创建。子实例终态为持久事实，维护进程按子实例编号发出唯一的 `workflow.child.terminal` 事件。父节点输出和续跑作业同事务提交。事件重放校验等待订阅和子实例两项身份，旧尝试的迟到事件不会推进新尝试。 |
| 失败、人工决策与取消 | 父节点可选择结束父流程、带失败状态继续、自动重试一次、等待人工决策。人工决定检查父子两端的查看和运行权限及父实例控制者身份，重试复用固定发布版本和原始子输入。首次调用与人工重试合计最多三次。父取消可传递至未结束子实例，也可脱离关联让子继续。 |
| 结果与呈现 | 成功时父节点得到 `status`、`attempt`、`result`。可用 `childResultPath` 从子结束节点声明的结果选择字段或数组元素。配置的字段路径缺失或按失败继续时，`result` 为 `null`。查询对端有独立查看权限，只有单端权限的账号在父实例返回的执行快照中也看不到另一端的绑定标识。 |
| 数据、运维与回退 | [关系表定义](../../../drizzle/workflow-run-link-schema.ts)及 [0049 迁移](../../../drizzle/0049_governed_capabilities.sql)新增 `workflow_run_link`，等候类型增加 `child`。部署 `FLOW_DURABLE_SUBFLOW_ADMISSION=false` 后可暂停新增父调用和发布，在途父、子实例仍可收尾。回退应用前清点关系表中的 `waiting` 和 `manual`，完成或按业务决定终止后，再撤下支持持久调用的 Worker。历史父版本仍须由兼容版本读取。 |

## 真实验收

| 场景 | 证据与通过条件 |
| --- | --- |
| A55、A56 | 在独立 MySQL 8.4 中发布带人工节点的子流程。父等待提交后注入 Worker 中断并重开 Worker。随后发布另一子版本、办理原任务，确认一个子实例、原子版本、一个父恢复作业和一个成功出口。实际重发同一子终态事件，并在重试后投递上一子实例事件。 |
| A57 | 用四种失败策略分别终结子实例，检查父状态、尝试数、固定摘要、人工决策的授权和重复提交。父暂停期间子完成，恢复后只续跑一次。父取消与子完成五轮竞争，父关联的作业无遗留租约。独立完成策略保留可继续办理的子任务。 |
| A58 | 编译自身引用和两层调用，诊断定位 `call/config.subflowId`。在真实数据库切换仅父或仅子查看者，检查运行详情、快照和对端链接。父运行提交后撤权，再让 Worker 领取，确认没有子实例和子等待订阅。 |
| 上线开关 | 同一父请求的重放仍返回原实例。关闭准入后新请求被拦截，在途父实例仍完成审批及结果回读。 |
| 复验入口 | [MySQL 专项](../../../server/durable-subflow.integration.test.ts)和[正常 HTTP 链路](../../../scripts/durable-subflow-acceptance.mjs)。HTTP 脚本用普通登录发布和启动，记录合成项目及父子 ID，最后只归档本次项目。目标与凭据由环境变量提供，目标声明遵循[全仓测试约束](../testing.md)。 |

本轮真实 MySQL 专项九组通过。并行场景分别向右、左子实例发送消息，在第一个完成后核对父仍等待，再核对两个独立返回字段和唯一汇聚出口。同步快照、作业状态等六个测试文件共 44 项通过。运行预检与快捷导航两个测试文件共 29 项通过。

2026-11-19 本机独立 MySQL 和 HTTP 服务的合成业务 `CHILD_F796E8E0` 已归档。父实例 `2aaed680-6ca5-4a66-b75f-76f13e3b7a63` 固定子版本 v2。子流程更新到 v5 后，子实例 `e9ff16bb-e794-49ea-9dde-62452e5dfe05` 完成审批，父子都到达成功终态，父输出与提交时的回执一致。另一份独立样本用真实 Edge 从编辑器修改失败策略、返回字段，保存并重新打开，再从父实例链接进入子实例并核对返回链接。取消操作后两个实例均为已取消，页面异常 0，样本已归档。

Windows PowerShell 在仓库根目录运行以下命令。MySQL 专项须使用已执行 0049 的独立数据库。HTTP 脚本须提供 `FLOW_ACCEPTANCE_BASE_URL`、相同目标的 `FLOW_ACCEPTANCE_CONFIRM_WRITES`，并从测试环境注入登录账号与口令。

```powershell
pnpm exec vitest run --config vitest.mysql.config.ts server/durable-subflow.integration.test.ts
node scripts/durable-subflow-acceptance.mjs
```
