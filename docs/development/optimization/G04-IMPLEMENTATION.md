# G04 助手后台回合实施与验收

客户悬浮助手和管理试聊都通过短事务接单。用户可以关闭面板、切换会话或刷新，再按原请求号核对。发送一条消息、批准一个提案、模型给出答案、业务操作生效分别有可查询的事实。旧客户端的 `assistant.message` 和 `assistant.decide` 仍返回会话，通过同一后台队列执行。

## 从页面追踪一次请求

| 入口 | 行为及可核对的依据 |
| --- | --- |
| 助手面板 | 浏览器保存会话、基准修订、原文及请求号。调用 `assistant.enqueue` 后显示排队或执行状态。新标签打开同一个历史会话时，通过 `assistant.job` 找到服务端作业。收尾按原请求读取 `assistant.get` 及其 `requestCommitted`。 |
| 接单 | 锁定账号和会话。相同会话、请求号、修订及内容返回同一作业。改内容或抢占在途回合返回冲突。请求号与内容摘要留作重放依据。 |
| 消费 | 使用 MySQL 8 的 `FOR UPDATE SKIP LOCKED` 认领。30 秒租约，每 7.5 秒续租，每个作业最多领取三次。调用模型期间释放会话行锁和连接。提交时用同一租约、未过期的数据库时钟、原修订和实时权限同时核对。 |
| 身份与工具 | 接单记下身份版本。每次使用工具，重新读取账号状态、项目权限及助手现在允许的工具。写操作在结构化提案确认后进入原领域命令。管理试聊在确认阶段生成模拟结果。 |
| 完成 | 助手消息、任务状态、会话修订与作业终态在同一事务写入。成功返回的模型编号及完成 ID 附在本次会话回合。已完成回合的作业副本移除用户原文，历史仍按现有会话规则读取。 |
| 运维 | Agent 配置页的“助手后台作业”显示当前积压、最老排队时间、活跃及过期租约、24 小时最多最近 1000 个终态样本的耗时和失败数。本实例的连接数统计只覆盖助手的数据库事务。 |

实现入口为[助手 UI](../../../client/src/components/AssistantChat.tsx)、[运营核对页](../../../client/src/components/AssistantOperations.tsx)、[路由](../../../server/assistant-router.ts)、[作业及租约](../../../server/assistant-jobs.ts)、[消费者](../../../server/assistant-job-worker.ts)及[新增表](../../../drizzle/assistant-job-schema.ts)。

## 状态与恢复决策

| 状态 | 用户动作 | 服务端恢复 |
| --- | --- | --- |
| queued | 查看、取消排队或离开页面 | 同会话其他意图会得到冲突。已取消的请求号保留取消回执，用户可另发新请求。 |
| running | 查看请求号，可到另一标签接续 | 只有未到期的当前令牌可提交。消费者中止后，其他进程可以接管。只读模型请求可能再次调用，已确认的业务命令始终沿用原提案操作号。 |
| completed | 按原请求打开消息、找到提案或真实业务结果 | 回读会话修订及消息，旧同步调用与新接口共享回执。提案的会话状态仍可为“等待确认”。 |
| failed | 阅读模型配置、服务中断、输出、工具、权限、资源或版本原因，按页面提示纠正 | 已失权或过期的结果不能覆盖较新会话。正常的模型失败仍留下用户可读的回合。 |
| needs_review | 继续查看本次提交，其他会话仍可工作 | 冻结此会话的新派发。管理员按操作号、目标资源、请求时间查询业务记录。登记“生效”或“未生效”和业务证据编号后，追加可追溯的会话回执与管理员审计记录。重复登记同一结论只生效一次。 |
| cancelled | 可继续编辑未发出的原文 | 取消和领取竞争时按锁定的作业状态判定。已派发的业务动作通过领域回执核对。 |

下游模型使用供应商自己的计费和请求标识。消费者在供应商接收请求后中止时，恢复可能产生额外模型调用。页面、领域命令与会话通过操作号和修订防止重复产生业务副作用。

### 已确认的业务写入

| 动作 | 业务与助手之间中断后的判定 |
| --- | --- |
| 创建流程目录 | 在同一个 MySQL 事务保存目录、操作摘要和包含目录 ID 的回执。重启后读取原回执，再补会话。 |
| 创建草稿、水印 | 沿用原领域的资源创建记录、操作号或设置审计。相同提案查询既有结果。 |
| 正式启动流程、创建数据标签、复制流程 | 把助手生成的稳定键传给领域命令。助手已预约但缺少回执时，用原键与账号、流程或项目范围查领域记录。 |
| 其他工作台写操作 | 先预约，再调用原业务过程。能判定的拒绝持久化。预约存在且缺乏业务结果证据时，转入人工核对。用户重复点击、Worker 接管、运维登记均不会再次派发该操作。 |

## 部署、扩展和回退

迁移 `0049_governed_capabilities` 包含 `assistant_turn_job`，升级顺序及回滚身份见发布记录。应用进程默认同时启动助手消费者。需要独立扩容时，使用相同的已迁移数据库及模型配置，在运行镜像中执行以下 Linux 容器命令。独立进程无需监听 HTTP 端口。

```sh
node dist/index.js --assistant-worker
```

- `ASSISTANT_WORKER_ENABLED=false` 让某个 Web 实例只接单，独立消费者使用 `true`。每个实例默认同时处理两项，可以用 `ASSISTANT_WORKER_CONCURRENCY` 在 1 到 6 之间调整。
- `ASSISTANT_JOB_INTAKE=paused` 停止新请求入队。已有请求号仍可查、可重放，消费者继续完成在途工作。退回旧运行镜像前，将排队、执行中、过期租约和待人工核对逐项处理完毕。
- 丢失回执时从会话和请求号查状态。对结果不确定的外部操作，保留原回执、业务编号和核实结论。部署后先用两条合成消息确认模型可用，再按实际额度批准容量测试。

## 真实验收

| 场景 | 所用环境与断言 |
| --- | --- |
| A63 | Windows 11、专用 MySQL 8.4。两个消费者在两个受控慢模型请求待返回时，对两个会话执行 `FOR UPDATE NOWAIT` 均可立即取得锁。相同键重放只有一个作业，变更内容或同修订新意图被拒绝。 |
| A64 | 正常业务服务实际写入流程目录，然后保留尚未完成的助手作业并过期原租约。下一消费者接管后，业务行只有一份，原请求的会话修订只增加一次。另用缺少领域依据的旧预约，验证待核对、权限限制、证据登记以及重复登记。 |
| A65 | 提案排队后撤回助手工具权限，消费者处理时拒绝，目标目录数量为零。管理试聊显示模拟确认，目标目录数量仍为零。 |
| A66 | 390 像素 Edge 打开两个标签。模型接到第一请求后，测试终止应用进程，以 Web 与独立消费者进程重新启动。两个标签找回同一请求，领取两次，提交一次，消息修订为 1。老会话按原请求号映射既有回执。 |
| A67 | 隔离库、单个独立消费者、并发度 2、受控 HTTP 模型响应延迟 220 毫秒。6 个会话同时接单并重放，6/6 完成。接单 108–127 毫秒。以客户端 700 毫秒轮询计，端到端 P95 和 P99 均为 2575 毫秒。结束时排队、租约、过期和待核对均为零。本次采样 Web 侧助手事务连接峰值为 6。该样本可比较版本，生产容量目标签收仍需选定供应商负载、配额与目标。 |

并发验收中曾出现不同会话同时首次接单返回 500。会话写入已经通过会话行互斥，队列表空范围无须再加排他锁。改用 READ COMMITTED 和短事务行锁，并对 DB 内的可重试事务有限重试后，六会话重放通过，已加入专项回归。

Windows PowerShell 可以在专用、已迁移的测试库上运行以下门槛。第一条使用本项目 `DATABASE_URL` 指定的测试库。第二条只访问显式选择的测试站点，使用运行环境已有的测试登录和模型配置。对端需提供本次回复的模型 ID 或完成 ID。脚本默认同时发两条合成消息，留两份验收会话，输出请求号、作业号、修订、模型回执和延迟。真实供应商和部署版本的实测结果以[整体实施记录](IMPLEMENTATION.md)为准。

```powershell
pnpm exec vitest run --config vitest.mysql.config.ts server/assistant-job.integration.test.ts server/assistant-store.integration.test.ts server/assistant-workspace.integration.test.ts
node scripts/assistant-job-acceptance.mjs
```
