# G03 内部目录批量导入

项目方确认账号由本系统管理。业务中心的导入菜单和人员与权限的组织架构页均可打开“内部目录批量导入”。一个批次最多 200 行，浏览器接受 256 KiB 以内的 UTF-8 JSON。目录管理员可下载可直接修改的模板。

## 文件合同

| 集合 | 持续标识 | 写入字段及规则 |
| --- | --- | --- |
| users | 小写用户名 | 姓名和可选邮箱。省略邮箱保留现值，传 null 清空。新建账号为普通内部账号，应用时为每个账号单独输入初始口令。文件遇到口令、角色等未定义字段会被拒绝 |
| units | 大写部门编码 | 名称和新部门的上级编码。同批部门按依赖顺序创建。同名不同编码可以共存。现有部门调整上级需使用原组织树操作 |
| memberships | 用户名和部门编码的组合 | 增加归属或更新岗位。新增归属为非主部门，未填写的岗位和既有主部门得到保留。省略已有关系时保留该关系 |

```json
{
  "version": 1,
  "users": [{"username":"lin.q","name":"林青"}],
  "units": [{"code":"OPS_CN","name":"运营部"}],
  "memberships": [{"username":"lin.q","unitCode":"OPS_CN","title":"运营专员"}]
}
```

## 权限和数据边界

`directory:preview` 可授给系统范围的自定义角色。持有人可生成、查看自己创建的预览。拥有 `iam:manage` 的操作者可以查看并应用已交接的批次。服务在组织写事务中重新核对账号状态、授权和版本。不同一方使用同一批次时，审计分别记录预览者与逐行实际操作人。账号管理密码规则同样适用于导入的新账号。批次、审计和返回值均保留目录资料、状态及对象标识。初始口令只在应用该行时传输并生成带盐的密码摘要。

## 从预览到回退

1. 上传文件时服务校验格式、重复标识、循环、缺失引用与目标状态，保存原资料镜像。预览期间只写批次与审计。文件内未出现的对象继续使用原资料。
2. 管理员核对新增、更新、相同和冲突。点击“应用此行”或“应用全部就绪行”。关系行在其引用的账号和部门之后执行，跨文件的引用要在预览时已存在。中断后选择原历史批次继续，最近 50 个批次可从界面打开。
3. 每行在同一事务内锁定批次、复核现有目录及引用，提交业务资料、写后镜像和授权审计。双击、并发提交或重放同一行返回保存的对象 ID。当目录已另改，保留人工修改并标记冲突，重新上传修订文件可生成新预览。
4. 回退先撤关系，再处理部门与账号。资料更新可恢复仍匹配写后镜像的字段。仍未使用的新增账号和部门以停用收尾。存在登录、授权或其他关联时保留对象并返回原因；人工变更受到写后镜像检查保护。

隔离 MySQL 8.4 已验证观察者、普通用户和管理员的边界、批次写入原子性，以及审计和批次中无口令。HTTP 套件通过应用登录生成真实目录，另一个批次修改账号后，旧预览被判为冲突。测试最后停用自己创建的账号和部门，撤回自己建立的成员关系。远程部署身份与实际运行结果见[实施与验收记录](IMPLEMENTATION.md)。
