# 审计整改与验收记录

基线为 `8964f07`。产品范围、原始缺陷和测试覆盖见[完整审计报告](REPORT.md)。本轮落实根目录 [AGENTS.md](../../../AGENTS.md) 与 [Agent.md](../../../Agent.md)，现有功能的修复使用真实 MySQL、通过 HTTP 启动的应用和 Edge 复验。以下编号沿用[验收场景](ACCEPTANCE.md)。

| 任务 | 已交付的行为 | 实测记录与后续验收 |
| --- | --- | --- |
| F01 | 四个历史浏览器脚本移除明文凭据回退。旧脚本统一要求显式环境及写入确认。跨 SSH 的夹具绑定同主机和指定容器，容器内夹具只访问自身回环 | 已修改的 98 个脚本通过 Node 语法核查。目标校验单测覆盖缺凭据、未确认及错误目标。身份处置需要管理员轮换与会话撤销记录 |
| F02 | Compose 默认回环绑定，站点模板提供合法证书的 HTTPS。在现有公网端口升级请求，拒绝明文提交 | 服务器独立回环监听器预演后切换正式代理。外部 GET 308、HTTPS 就绪 200、证书验证成功。Edge 用本轮普通账号登录、刷新、退出后再次访问。Cookie 为 Secure、HttpOnly、SameSite=Lax，测试账号已停用 |
| F03 / F04 / U02 | 完整 CSV 预检，通过后按批次逐行提交。冲突保留成功行，新旧修订按行回读，对应创建审计和项目在同一事务内落库。界面提供原批纠正、历史与错误下载 | 真实 MySQL 验证并发占码、同批重放、不可改动成功行、其他账号不可读取。Edge 验证坏行零写入，纠正后两行各一次，CRLF 与引号保存完整，刷新可回读，缺闭引号零写入 |
| F05 | 三处人工发起数据流程的入口共用操作键，支持按键核对和继续操作。服务端在同一事务绑定输入、原版本、运行和作业 | MySQL 检查重复操作指向同一运行、相同键改变输入引发冲突、单个作业、完成后核对时读到真正终态。旧客户端和调度仍走原有合同 |
| F06 | 签署测试在截止时间内等待该运行的 start、resume 作业终态，继续断言作业数量、出口和重复办理 | 真实 MySQL 全量和定向签署复验通过 |
| F07 | 路由夹具按所读修订审核，广播节点绑定汇聚。数据质量分开验证创建拒绝和运行结果，指标脚本生成自己的等待和终止样本 | 两套空库各执行三组 HTTP 验收。另发现应用与数据库时区相差 8 小时会延后定时节点并夸大耗时。计时改用数据库时钟，新增实测墙钟上限。两库的 1 秒等待样本分别记录 1653 ms、1685 ms |
| F08 | 流程模型节点保存请求模型、返回模型、配置修订、完成 ID 和可得的逐次 HTTP 回执。节点详情展示旧记录或供应商缺失信息 | 运行时保留既有费用与用量计算；网络错误只保留状态、请求编号等诊断字段。实际模型供应商的本轮回读单独登记 |
| F09 / U06 | 助手历史支持范围约束、稳定排序、游标、检索及按修订向前取消息。试聊、客户会话和当前项目仍分别鉴权。历史面板提供继续加载和新消息定位 | 真实 MySQL 检查相同时间续读、跨范围游标拒绝、消息不重不漏和当前修订。旧会话和旧客户端接口保留 |
| U01 / U03 | 受控弹窗回到触发控件，小屏业务列表保留主要操作并将次要字段放入详情 | 真实 Edge 在普通与减少动效模式均将焦点送回“新增业务”。四档宽度 360、390、768、1440 下，首行主操作右边缘分别为 315、345、725、1337 像素 |
| U04 / U05 | 画布定位扣除重叠检查器和定位控件。工作台以任务 ID 保留行，回焦到触发者，可继续办理。日历轮询更新已有事件状态 | 画布和轮询验收应结合实际 DOM 命中、动作后的焦点和持久化结果。仅凭构建或关键字断言不能证明真机操作体验 |
