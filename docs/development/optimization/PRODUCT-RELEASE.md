# Flow AI Engine v1.0.0 产品发布验收

发布面向电脑网页端。系统使用内部账号和部门，外部数据读写使用独立联测服务。状态、控制和数据流程均以发布版在应用、Worker 和 MySQL 中执行。桌面浏览器使用 Windows Edge 149，主要视口为 1600×1000，前一轮交互复验使用 1440×900。[三类流程、内置节点与运行截图](../../workflow-guide.md)

## 发现的问题与修改

| 问题 | 原因与修复 | 复验 |
| --- | --- | --- |
| 时间筛选漏数据、带时限的授权延后失效 | Windows 应用按系统本地时区编解码 SQL 时间，MySQL 使用 UTC。应用共享连接池统一以 UTC 传送 `Date`，连接建立时设置 UTC 会话；Drizzle 复用同一连接池。现有列和记录无需迁移。 | 在应用为 UTC+8、MySQL 为 UTC 的专用环境，四个原来漏行的入口均恢复，数据运行历史也继续命中。组织继承和流程成员到期后拒绝原权限。真库回归对绑定参数、读取值和 Drizzle 会话分别断言。[时间约定](../database.md) · [MySQL 回归](../../../server/db-time.integration.test.ts) |
| 两个历史验收脚本预期过时 | 内部目录增加 `directory:preview` 后，当前版本的系统内置授权共有八个。旧版本的对照仍按七个校验。另一个脚本原来匹配英文登录文案，改为验证 HTTP 401。 | 用独立 HTTP 与 MySQL 复验当前版本的授权代码、委派管理员、权限撤销及会话失效。[权限来源](../../../scripts/permission-sources-acceptance.mjs) · [流程成员状态](../../../scripts/workflow-member-status-acceptance.mjs) |
| 旧验收要求从浏览器取得一个既有运行，独立环境没有该夹具 | 产品验收每次自行创建模拟业务、发布所需流程并读取本次运行和结果。Edge 运行表单提交本次消息实例，再按浏览器回执核对其输入及终态。 | 输入 `00123` 保持文本，`10` 保持数值，`{"enabled":true}` 保持对象。按原业务键发送消息后，结束节点执行一次。多结果集在桌面可分别选择，金额名称去除首尾空格并保留对应行。[产品验收脚本](../../../scripts/product-release-acceptance.mts) |
| 发布链缺少可重复取得的构建制品，README 的状态描述落后 | 候选分支以已提交的源码构建 Linux amd64 镜像，追加源码归档、SHA-256 和包含构建身份的清单。说明补充三类实跑截图、概念和内置节点，保留在线演示。 | 用候选制品做远程签收，再以同一制品交付 GitHub Release。清单、检查结果和发布地址可从发布页核对。[构建工作流](../../../.github/workflows/release-candidate.yml) · [发布页](https://github.com/Azurefly/flow-ai-engine/releases/tag/v1.0.0) |

## 需求追踪与实测结果

表内“本轮”使用重新构建的应用和隔离 MySQL。写操作只创建本轮的合成账号、部门、项目和实例。结束后项目归档、账号及部门停用，保留审计。前序证据见[基线需求矩阵](REQUIREMENTS.md)、[整改实测](IMPLEMENTATION.md)和[复查回执](FOLLOWUP-20261120.md)。

| 需求 | 覆盖场景、可见结果与证据 |
| --- | --- |
| R01 登录、注销、禁用及撤权 | 本轮从内部账号登录和读取会话，取消原授权后再次访问即被拒，停用账号登录返回 401。公网走 HTTPS 并核对会话、刷新和注销。 |
| R02 用户目录、系统角色及业务授权 | 本轮观察员未获授权时无法读取，获业务查看者授权后可打开详情，发起仍返回 403，撤权后详情不可见。专用脚本还复验直接、继承、多来源、过期、禁用与委派授权。 |
| R03 账号创建与模型建议 | 本轮创建四个账号、分别登录并核对原 ID。MySQL 覆盖审计原子性。模型建议沿用远程显式确认前的样本，正式批次规模须有专项约定。 |
| R04 组织、工作域与设置 | 创建两层部门、设置负责人及三个主部门成员关系，读回成员数。隔离库复验并发唯一主部门、部门权限组继承、组织写入与审计。工作域与系统配置由真库专项覆盖。 |
| R05 项目身份、成员、部门及端点 | 本轮项目权限进出、运行详情隔离、账号失权均经真实 HTTP 验证。项目端点授权及改写由独立真库覆盖，外部可达性按配置验证。 |
| R06 CSV 业务导入与纠错 | 前序 Edge 完成失败行纠正、原行重传、审计回读和防重复。本轮 MySQL 回归重跑冲突、并发和写入恢复。 |
| R07 草稿、审核、发布及恢复 | 本轮使用三类草稿，按修订审核并发布，预检后才正式运行。版本竞争、历史版本、审核重放与恢复由真库覆盖，已发布实例读取自己的定义快照。 |
| R08 仓库、导入导出和复用 | 真库复验 JSON 导入、保存、重读、再解析和复制；前序三类流程和 30 类节点模板由独立样例核对。 |
| R09 状态流程与参与人 | 请假实例依次办理两级审批，共 19 条节点运行。参与人样例经历提交、领取、撤回、旧待办失效、重放原命令、换人办理，结束时读到三张人员卡。 |
| R10 条件、循环、并行与汇聚 | 两种身份完成并行工单复核。第一条完成时未汇聚，第二条结束后仅汇聚一次。循环和普通路由、默认及未匹配出口有既有真实 HTTP 和本轮回归。 |
| R11 签署、转交及重复办理 | 本轮回读已办及取消后的待办，任务撤回重放获得同一结果。签署、转交、候选资格和事务回滚由真库专项复验。 |
| R12 已启动流程与运行诊断 | 真实 HTTP 复验暂停时办理返回 409，恢复同一个任务，取消后待办不可再办。业务列表、待办、已启动流程、流程运行历史、数据运行历史五个时间入口均命中本轮记录。指标与作业恢复沿用已有实测和真库回归。 |
| R13 资源探查、执行和血缘 | 真实 inline 订单资源完成启动和六份节点产物回读。G01 的 API 分页、CSV 和外部写回另以独立服务签收。 |
| R14 变换、关联、函数、筛重及质量 | 四条订单经过筛选、质量门与聚合，最终华东 2 单合计 200，华南 1 单合计 60。旧脚本复验真实 join 和函数，MySQL 回归覆盖质量不达标、资源拒绝及计划快照。 |
| R15 人工数据运行与结果 | 本轮从已发布数据流程接单、等待结果、核对两个独立结果集及预览字段。前序 Edge 三个运行入口都覆盖响应丢失和原回执核对，本轮重跑其中的服务端幂等断言。 |
| R16 调度与取消 | 本轮真库覆盖原生时间桶幂等、暂停、修订冲突及运行取消。旧托管服务的删除接口待有专用上游验收对象。 |
| R17 端点、模型配置和流程 LLM | 前序真实三节点流程对接供应商并回读请求模型、返回模型和完成 ID，本轮回归覆盖各字段、端点授权和缺失回执。 |
| R18 助手管理、发布与试聊 | 同一运行逻辑覆盖管理草稿、发布、试聊与会话范围。前序桌面完成中文组合输入、键盘取消、确认和试聊，写入分别为 0、1、0 份业务记录。 |
| R19 客户助手提案、确认、队列及回执 | MySQL 覆盖确认、去重、失权和长回合恢复。G04 以部署配置的真实模型核对两个专用会话的完成回执。 |
| R20 助手历史与消息恢复 | 0050 索引和独立 MySQL 审查多种范围、游标、同秒排序和下一页。桌面输入与刷新、历史可见性和快捷操作有浏览器证据。 |
| R21 桌面弹窗、焦点和反馈 | 前序真实 Edge 复验业务对话框回焦、键盘展开、操作失败与重试。本轮在运行表单操作原生控件并用运行编号回读服务端。 |
| R22 桌面画布、位置与工作台连续操作 | 本轮实测三类运行图、选中节点和切换数据终端结果。前序桌面复验减少动效、浏览器返回、后台轮询及画布懒加载。[动效评审和开源参考](../ui-motion-review.md) |
| R23 持久父子实例 | G02 核对父实例等待、子版本冻结、人工任务处理后父实例继续、各自权限和单一结算。MySQL 覆盖崩溃恢复及暂停后恢复。 |
| R24 内部目录批量导入 | G03 核对预览零业务写入，批量应用各行仅落一次，遇人工改名冲突留存，回退并回读。 |
| R25 部署与运营 | 核对迁移、应用镜像、MySQL 实例延续、HTTPS 静态资源摘要、浏览器会话与备份完整性。部署及实际第三方回执随发布页登记。 |
