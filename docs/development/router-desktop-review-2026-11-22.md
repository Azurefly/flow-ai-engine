# 路由编辑与相邻配置的桌面实测

基线为 `42e6e14`。在 Windows Edge 149 的 1600 × 1000 窗口打开现有流程，选择路由节点和分支，复现后再以专用 MySQL 库中的合成流程编辑、保存和回读。相邻功能的结论来自操作浏览器时看到的界面。

## 本轮修复

| 用户操作 | 基线表现 | 整改后的浏览器结果 |
| --- | --- | --- |
| 打开「达到通过人数」再看逐项条件 | 同一操作名称和「1 人中至少 1 人通过」出现两次，需逐个展开才能看到实际人员。 | 分支概览只显示一次「2 人中至少 1 人通过」。展开逐项条件后，两条分别写出各自的审批员。 |
| 按名称核对分支去向 | 右侧只有流向文字，画布上多条连线并排，无法确认对应哪条。 | 每个真实连接节点都可点「定位」。画布同时高亮本条线和目标节点。新增未接线的分支显示「未连线」。隐式默认出口也可以定位。 |
| 编辑某一项条件 | 单个角色条件下面仍有分支名、附加数据、优先级等上级编辑项。「取反」和角色代号还要在脑中换算。 | 概览把命中条件放在一起。进入角色、数据或审批人数的编辑页时，只出现该项的字段和返回入口。角色用名称显示一次，「没有所选的任何角色」可以直接选择。 |
| 改优先级并返回 | 配置位置藏在高级设置里，列表也看不到数值。 | 优先级放在分支设置区。列表显示数值并按从高到低排列，默认分支单独展示。把优先级从 10 改成 120 后，返回列表立即排首位，保存刷新后仍在首位。 |

在合成流程验证了显式默认分支、普通路由的隐式默认出口、业务数据条件、人员条件和审批组合。分支排序沿用引擎的优先级和同值顺序。压缩构建由 524.93 KiB 增至约 526.4 KiB，本轮整体压缩预算为 527 KiB。

## 相邻界面走查

| 入口与操作 | 浏览器里观察到的结果 | 建议与验收 |
| --- | --- | --- |
| 普通条件节点 → 判断规则 → 分支代号 | 能配置比较和看到成立／不成立代号。右侧两个页签都看不到各自的目标名称，要回画布找线。 | 优先在「判断规则」下直接显示两条去向，点击定位到该连线和目标。两条线接到同一节点以及一条未连线时也要分别辨认。 |
| 操作节点 → 结果与分支 → 点击「下一步」 | 已显示同意、拒绝的下一步名称。点击名称后画布没有定位，结果代号、出口代号和业务名称也在同一组表单中。 | 概览先显示「办理结果 → 下一步」，点目标定位，点结果只打开该项配置。技术代号放到高级字段。 |
| 状态节点 → 可用操作 → 点击「撤回」 | 能读到动作名称，点击仍停留在当前状态的面板。 | 将已连接的操作做成可定位入口。点击时高亮连接，并能从操作回到原状态。 |
| 普通路由 → 数据条件 | 能定位分支目标。条件概览里的启动输入仍显示为 `{{input.amount}}`。 | 引用项用「启动输入 · 字段名称」呈现。需要核对字段路径时再展开详细信息。 |

以上走查项按本次实际操作记录，适合后续分别按表中的步骤验收。生产流程与人员截图留在私有工作区。
