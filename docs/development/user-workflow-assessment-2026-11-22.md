# Flow AI Engine 电脑端使用评估与整改报告

评估基线为 `7082247`。从流程设计者、办理人和权限管理员的任务出发，检查页面能否让人找到入口、理解下一步、完成操作并回查结果。浏览器使用 Windows Edge 149，视口为 1440 × 900 与 1600 × 1000。涉及写入和并发的场景使用独立 MySQL 库、合成业务数据及本机应用，Worker 的状态与控制流程通道并发设为 4。远程基线应用和数据库健康，HTTPS 就绪检查正常。

## 基线实测

并发提交由同一已发布的控制流程承接。32 次同时发起含一组 8 次相同提交键，得到 25 个不同实例，25 个均成功。发起响应齐全约需 1.67 秒，全部成功约需 10.30 秒，详情仍可取回原始输入。该用例覆盖有界并行与重复提交保护。

用上述 25 个实例测了 60 次列表查询，12 路并发，预热后记录请求、完整响应读取和 JSON 解析用时。中位数 1,542 ms，P95 5,554 ms，响应稳定在 2,646,104 字节。完整编号和带 `RUN` 的前八位各命中 0 条。列表字段中发现定义快照、输入、上下文及内部租约字段。

在草稿画布选中还有空出口的“开始”，通过节点库添加“条件”，节点出现且连线数保持为零。条件配置同屏有“待判断的数据”“比较方式”“成立分支句柄”“不成立分支句柄”，画布出口本身已显示中文成立与不成立。

## 整改后的实测

| 验收项 | 电脑端或 HTTP 实测结果 |
| --- | --- |
| 实例检索和回查 | 完整编号、带 `RUN` 的短编号和发起账号均命中。25 条记录按三页读取，无重复或漏项。Edge 用短编号、成功状态和日期同时筛选，打开独立实例，刷新后返回，原视图、筛选和每页条数均保留。 |
| 列表数据和并发 | 同一批 25 条记录每页为 23,879 字节，比基线减少 99.1%。12 路共 60 次读取全部成功，中位数 201 ms，P95 215 ms。新版列表，包括旧的无游标列表，均返回概要字段。具备流程查看权限的用户仍可在详情读取原始输入。 |
| 作业提交 | 同时发起 32 次，含 8 次相同键，最终仍为 25 个不同的成功实例。最近一次对照中发起响应齐全约需 0.90 秒，全部成功约需 11.83 秒。流程执行耗时仍随任务内容与环境变化。 |
| 画布连接和配置 | 通过“接到当前节点”添加一个条件节点和一条线，一次撤销恢复原节点数与连线数。条件面板将“判断规则”与“分支代号”放在不同页签。修改一个节点名称，保存草稿并刷新，可回读新名称。 |
| 列表与详情权限 | 无关账号在列表中查不到实例，直接打开详情也被拒。参与者可以从工作台查看自己的办理记录，页面清楚说明其查看范围。账号经部门角色获查看权限后，可读原实例详情。 |
| 角色分配与撤回 | 在 Edge 为有部门授权的账号选择同一角色，看到具体部门。个人授权提交后，重新打开显示已有直接授权且禁止重复提交。撤销个人授权仍能查看实例，撤销部门授权后再次打开详情被拒。 |
| 运行诊断 | 从管理员接口读回当前进程的三路并发槽位为 4、4、1。用于了解单进程设定，持续吞吐须按业务流量另测。 |

| 用户任务 | 现有能力与查到的风险 | 下一批可直接领取的验收任务 |
| --- | --- | --- |
| 建项目、创建流程、从草稿发布 | 前序真实验收覆盖三类流程的草稿、审核、发布和版本保护。项目协作者在编辑、审核、发布之间切换时，需要知道为什么还不能发布。 | 用普通设计账号完成新建、补配置、送审、驳回重改，再由发布账号完成上线。各阶段显示当前修订、影响范围和下一位可处理人。 |
| 编辑和读懂大画布 | 当前有搜索、定位、相邻节点视图和撤销。分支、并行、循环的读图成本取决于标签和节点密度。 | 用 100 节点含并行分支的桌面夹具，记录冷启动、缩放、键盘导航及定位耗时。覆盖不同有效出线；为插入已有连线设计显式确认，保留原分支和循环语义。 |
| 办理、回查和排查故障 | 任务有待办、已办、任务详情与独立实例画布。状态和控制流程工作台读 `workflow_run`，数据流程运行中心读 `dataflow_run`。跨项目定位数据流程仍需切入口。 | 用两类来源的有界查询建立统一只读检索，按流程类型和项目筛选，合并稳定游标。服务端分别判断权限，详情按类型继续进入现有页面。加上未知编号、历史版本、失败节点重进三类用例。 |
